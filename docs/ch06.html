第 6 章

RAG 基础与 ChromaDB

模型不知道你公司的产品手册，也不知道上周才发布的公告。把这些资料全部塞进提示词？太长、太贵。 RAG（检索增强生成）的办法是：提问时只把最相关的那几段找出来交给模型。 这一章不用任何框架，从零搭一个最小的 RAG，把原理看透。

本章目标

  • 理解「语义搜索」和关键词搜索的区别
  • 知道嵌入（embedding）和向量库是什么、为什么需要它们
  • 掌握 RAG 的两个阶段：入库与问答
  • 用 ChromaDB 存入文本并做语义检索
  • 亲手写一个 RAG 问答函数，并让它在不知道答案时老实承认

语义搜索：按意思找，而不是按字面找

传统搜索靠关键词匹配。问「度假去哪儿凉快」，它找不到一篇写着「避暑胜地推荐」的文章，因为一个字都对不上。 语义搜索比较的是意思，而不是字面。

嵌入：把意思变成坐标

实现语义搜索的关键是嵌入模型（embedding model）。它把一段文字转换成一长串数字（比如 1536 个），叫做向量。 你可以把向量想象成这段话在一个「意思空间」里的坐标：意思相近的文字，坐标也挨得近。

RAG 设计模式

有了语义搜索，RAG 的整体思路就清楚了。它分成两个阶段：

🔑 用一个比喻记住 RAG

普通的 LLM 问答是闭卷考试：只能凭记忆回答，记不清就可能瞎编。 RAG 是开卷考试：先翻到书上相关的那几页（检索），把内容摆在面前（增强），再作答（生成）。 答案有据可查，资料随时可以更新，而模型本身一个参数都不用改。

向量库

向量库（vector store）专门干两件事：存向量，以及「给我一个向量，快速找出和它最接近的那些」。 当数据量到百万级时，逐个比较就太慢了，所以它们使用近似最近邻（ANN）索引 —— 牺牲一点点精度换取数量级的速度提升。

向量「库」与向量「数据库」

向量库（library）向量数据库（database）
形态嵌在你的程序里运行独立的服务
数据通常在内存里，自己负责保存持久化、可增删改、支持元数据过滤
扩展性单机可分布式、多副本
适合原型、离线分析生产环境
例子FAISSChroma、Qdrant、Milvus、Pinecone、Weaviate

常见选择

从零实现 RAG

现在把「检索」和「生成」接起来。三个小函数，刚好对应 R、A、G：

from openai import OpenAI
openai_client = OpenAI(api_key=OPENAI_API_KEY)

# R：检索
def query_vector_database(question):
    results = tourism_collection.query(query_texts=[question], n_results=1)
    return results['documents'][0][0]

# A：增强 —— 把检索到的文本和问题拼成提示词
def prompt_template(question, text):
    return f'Read the following text and answer this question: {question}. \nText: {text}'

# G：生成
def execute_llm_prompt(prompt_input):
    return openai_client.chat.completions.create(
        model='gpt-5-nano',
        messages=[
         {"role": "system", "content": "You are an assistant for question-answering tasks."},
         {"role": "user", "content": prompt_input}
        ])

import OpenAI from "openai";
const openaiClient = new OpenAI();

// R：检索
async function queryVectorDatabase(question: string): Promise<string> {
  const results = await tourismCollection.query({ queryTexts: [question], nResults: 1 });
  return results.documents[0][0] ?? "";
}

// A：增强 —— 把检索到的文本和问题拼成提示词
function promptTemplate(question: string, text: string): string {
  return `Read the following text and answer this question: ${question}. \nText: ${text}`;
}

// G：生成
async function executeLlmPrompt(promptInput: string): Promise<string> {
  const response = await openaiClient.chat.completions.create({
    model: "gpt-5-nano",
    messages: [
      { role: "system", content: "You are an assistant for question-answering tasks." },
      { role: "user", content: promptInput },
    ],
  });
  return response.choices[0].message.content ?? "";
}

import dev.langchain4j.data.message.SystemMessage;
import dev.langchain4j.data.message.UserMessage;

// R：检索
static String queryVectorDatabase(String question) {
    var request = EmbeddingSearchRequest.builder()
            .queryEmbedding(embeddingModel.embed(question).content())
            .maxResults(1).build();
    return tourismCollection.search(request).matches().get(0).embedded().text();
}

// A：增强 —— 把检索到的文本和问题拼成提示词
static String promptTemplate(String question, String text) {
    return "Read the following text and answer this question: %s. \nText: %s"
            .formatted(question, text);
}

// G：生成
static String executeLlmPrompt(String promptInput) {
    return llm.chat(
            SystemMessage.from("You are an assistant for question-answering tasks."),
            UserMessage.from(promptInput)).aiMessage().text();
}

String trickQuestion = "How many columns have the three temples got in total?";

String tqPrompt = promptTemplate(trickQuestion, tqResultText);
System.out.println(executeLlmPrompt(tqPrompt));

用上面那个朴素的提示词，模型很可能会从自己的训练记忆里凑一个数字出来，或者干脆编一个。 这就是幻觉（hallucination）—— 而且用户完全分辨不出哪些内容来自你的资料、哪些是模型自己加的。

更安全的提示词

朴素版
Read the following text and
answer this question: {question}.
Text: {text}
安全版
Use the following pieces of retrieved
context to answer the question.
Only use the retrieved context to
answer the question.
If you don't know the answer, or the
answer is not contained in the retrieved
context, just say that you don't know.
Use three sentences maximum and keep
the answer concise.
Question: {question}
Context: {text}
Answer:

安全版多了三条约束：只用给定资料、不知道就说不知道、回答要简短。换上它之后，同一个陷阱问题会得到「I don't know」。

⚠ 这是 RAG 最重要的一条提示词纪律

一个会老实说「资料里没有」的助手，远比一个什么都敢答的助手有用。 只要是面向真实用户的 RAG 系统，提示词里都应该有「仅依据上下文回答，否则承认不知道」这类约束。

def my_chatbot(question):
    results_text = query_vector_database(question)          # R 检索
    prompt_input = prompt_template(question, results_text)  # A 增强
    prompt_output = execute_llm_prompt(prompt_input)        # G 生成
    return prompt_output

print(my_chatbot(question).choices[0].message.content)
# 可能的输出：There are three temples in Paestum. They were built by Greek colonists
#            and are in the Doric style.

async function myChatbot(question: string): Promise<string> {
  const resultsText = await queryVectorDatabase(question);    // R 检索
  const promptInput = promptTemplate(question, resultsText);  // A 增强
  return executeLlmPrompt(promptInput);                       // G 生成
}

RAG 术语表

术语含义
块 Chunk文档被切分后的片段，是检索的基本单位
嵌入 Embedding一段文本的向量表示；也指「把文本变成向量」这个动作
嵌入模型把文本转换成向量的模型。入库和提问必须用同一个
向量库 Vector store存储向量并支持相似度检索的数据库
集合 Collection向量库里的一个「表」
入库 / 索引 Ingestion / Indexing把文档切块、向量化、存入向量库的过程
检索 Retrieval根据问题找出最相关的文本块
上下文 Context检索到并放进提示词的那些文本
Top-k检索时返回最相近的 k 个结果
元数据 Metadata附在文本块上的额外信息（来源、日期、类别），可用于过滤和引用
幻觉 Hallucination模型生成了看似合理但没有依据的内容
接地 Grounding让模型的回答以给定资料为依据

小结

  • 语义搜索按意思而非字面匹配；靠的是把文本变成向量，再比较向量之间的距离。
  • RAG 分两个阶段：入库（切块 → 向量化 → 存储）和问答（问题向量化 → 检索 → 拼提示词 → 生成）。
  • 向量库负责存向量和快速找近邻；Chroma 上手最简单。
  • 入库和查询必须使用同一个嵌入模型，否则向量之间没有可比性。
  • RAG 提示词要约束模型「只依据上下文回答，不知道就说不知道」，否则它会用训练记忆补空，产生幻觉。
  • 一个最小的 RAG 只需要三个函数：检索、拼提示词、调用模型。
