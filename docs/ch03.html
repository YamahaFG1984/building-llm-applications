第 3 章

用 LangChain 做文本摘要

「帮我总结一下」是 LLM 最拿手的活。但如果要总结的是一整本《白鲸》，或者是散落在维基百科、Word、PDF 里的好几份资料呢？ 一次塞不进去，就得拆开来各个击破，再合起来。这一章学两种经典拆法：Map-Reduce 和 Refine。

本章目标

  • 理解上下文窗口为什么会成为瓶颈
  • 用 Map-Reduce 总结一份超长文档
  • 用文档加载器读取维基百科、Word、PDF、文本文件
  • 用 Refine 逐步精炼地总结多份文档
  • 拿到一个摘要任务时，知道该选哪种策略

问题：书太厚，窗口太小

模型一次能读的文字有上限，叫上下文窗口。一本《白鲸》大约有 30 万 token， 即使某个模型的窗口装得下，把整本书一次塞进去也又贵又慢，而且内容太多时模型容易「顾头不顾尾」，遗漏中间部分。

解决思路和人读厚书做笔记一模一样：一章一章读，每章写个小结，最后把小结汇总成全书摘要。

ⓘ 名字的由来

Map（映射）指「对列表里的每个元素做同一件事」，Reduce（归约）指「把一堆结果合并成一个」。 这个说法来自大数据处理领域，和你在 JavaScript、Java、Python 里用过的 map() / reduce() 是同一个意思。

用 Map-Reduce 总结一本书

把整个流程拆成三条小链，最后再接成一条大链。

① Split：按 token 数切块

每块 3000 token，相邻两块重叠 100 token。重叠是为了避免一句话正好被拦腰切断、两边都看不懂。 

# 输入：整本书的字符串；输出：[{'chunk': '...'}, {'chunk': '...'}, ...]
text_chunks_chain = (
    RunnableLambda(lambda x:
        [
            {'chunk': text_chunk}
            for text_chunk in
               TokenTextSplitter(chunk_size=3000, chunk_overlap=100).split_text(x)
        ]
    )
)

// 输入：整本书的字符串；输出：[{ chunk: "..." }, { chunk: "..." }, ...]
const splitter = new TokenTextSplitter({ chunkSize: 3000, chunkOverlap: 100 });

const textChunksChain = RunnableLambda.from(async (text: string) =>
  (await splitter.splitText(text)).map((chunk) => ({ chunk })));

// 按 token 数切分：每块 3000，重叠 100
var splitter = DocumentSplitters.recursive(
        3000, 100, new OpenAiTokenCountEstimator("gpt-4o-mini"));

List<TextSegment> chunks = splitter.split(Document.from(mobyDickBook));
💡 RunnableLambda 是什么

它把一个普通函数包装成 LangChain 的积木，这样自己写的任意逻辑也能用 | 接进链里。 后面你会大量看到它，作用通常是「调整一下数据的形状，好喂给下一步」。

// parallelStream() 让多个块同时请求模型 —— 这就是 map 阶段的「并行」
List<String> summaries = chunks.parallelStream()
        .map(chunk -> llm.chat(
                summarizeChunkPrompt.apply(Map.of("chunk", chunk.text())).text()))

StrOutputParser（TS 里叫 StringOutputParser）做的事很简单：从模型返回的消息对象里取出 .content 字符串。 有了它，链的输出就是干净的文本，方便交给下一步。

③ Reduce：把小摘要合成大摘要

summarize_summaries_prompt = PromptTemplate.from_template("""

summarize_reduce_chain = (
    RunnableLambda(lambda x:
        {'summaries': '\n'.join([i['summary'] for i in x])})
    | summarize_summaries_prompt
    | llm
    | StrOutputParser()
)

const summarizeSummariesPrompt = PromptTemplate.fromTemplate(`
Write a concise summary of the following text, which joins several summaries,

Text: {summaries}
`);

// 输入：[{ summary: "..." }, ...]；输出：最终摘要字符串
const summarizeReduceChain = RunnableLambda
  .from((items: { summary: string }[]) => ({

// 把上面三段包成一个方法，就是 Java 版的「map-reduce 链」
static String mapReduceSummarize(ChatModel llm, String text) {
    var chunks = DocumentSplitters
            .recursive(3000, 100, new OpenAiTokenCountEstimator("gpt-4o-mini"))
            .split(Document.from(text));

    var summaries = chunks.parallelStream()                                      // map
            .map(c -> llm.chat(SUMMARIZE_CHUNK.apply(Map.of("chunk", c.text())).text()))
            .toList();

    return llm.chat(SUMMARIZE_SUMMARIES                                          // reduce
            .apply(Map.of("summaries", String.join("\n", summaries))).text());
}
⚠ 注意费用

整本《白鲸》会切出上百块，也就是上百次模型调用。仓库里的 Moby-Dick.txt 已经是缩短过的版本， 完整版叫 Moby-Dick_ORIGINAL_EXPENSIVE.txt —— 文件名已经说明了一切。练习时先用短的。

总结多份来源不同的文档

现实中更常见的需求是：关于同一个主题（书里的例子是意大利古城帕埃斯图姆 Paestum）， 手头有一篇维基百科、一份 Word、一份 PDF、一个文本文件，要综合出一份摘要。

Refine：边读边改的滚动摘要

有了文档列表，当然可以再用一次 Map-Reduce。但它有个弱点：每份文档是独立总结的， 总结第三份的时候，模型并不知道前两份已经说了什么，于是容易重复，也可能在最后合并时把某份文档的要点挤掉。

Refine（精炼）换了个思路：维护一份「当前摘要」，每读一份新文档，就让模型在现有摘要的基础上修订。 就像你写读书笔记时，读完一章就回头补充、修改前面的笔记。 

refine_summary_prompt = PromptTemplate.from_template("""
You must produce a final summary from the current refined summary
which has been generated so far and from the content of an additional document.
This is the current refined summary generated so far: {current_refined_summary}
This is the content of the additional document: {text}
Only use the content of the additional document if it is useful,
otherwise return the current full summary as it is.""")

refine_chain = refine_summary_prompt | llm | StrOutputParser()

def refine_summary(docs):
    intermediate_steps = []
    current_refined_summary = ''
    for doc in docs:
        intermediate_step = {
            "current_refined_summary": current_refined_summary,
            "text": doc.page_content}
        intermediate_steps.append(intermediate_step)

        current_refined_summary = refine_chain.invoke(intermediate_step)

    return {"final_summary": current_refined_summary,
            "intermediate_steps": intermediate_steps}

full_summary = refine_summary(all_docs)
print(full_summary["final_summary"])

const refineSummaryPrompt = PromptTemplate.fromTemplate(`
You must produce a final summary from the current refined summary
which has been generated so far and from the content of an additional document.
This is the current refined summary generated so far: {current_refined_summary}
This is the content of the additional document: {text}
Only use the content of the additional document if it is useful,
otherwise return the current full summary as it is.`);

const refineChain = refineSummaryPrompt.pipe(llm).pipe(new StringOutputParser());

async function refineSummary(docs: Document[]) {
  const intermediateSteps: Record<string, string>[] = [];
  let currentRefinedSummary = "";

  for (const doc of docs) {
    const step = { current_refined_summary: currentRefinedSummary, text: doc.pageContent };
    intermediateSteps.push(step);
    currentRefinedSummary = await refineChain.invoke(step);
  }
  return { finalSummary: currentRefinedSummary, intermediateSteps };
}

const fullSummary = await refineSummary(allDocs);
console.log(fullSummary.finalSummary);

PromptTemplate refineSummaryPrompt = PromptTemplate.from("""
        You must produce a final summary from the current refined summary
        which has been generated so far and from the content of an additional document.
        This is the current refined summary generated so far: {{current_refined_summary}}
        This is the content of the additional document: {{text}}
        Only use the content of the additional document if it is useful,
        otherwise return the current full summary as it is.""");

String currentRefinedSummary = "";
for (Document doc : allDocs) {
    currentRefinedSummary = llm.chat(refineSummaryPrompt.apply(Map.of(
            "current_refined_summary", currentRefinedSummary,
            "text", doc.text())).text());
}
System.out.println(currentRefinedSummary);

注意这里没有用一条大链，而是一个普通的 for 循环。这很正常 —— 链适合「数据一路往下流」的场景；一旦需要循环累积状态，写普通代码反而更清楚。 第 5 章会介绍专门处理循环和状态的工具：LangGraph。

两种策略怎么选

Map-ReduceRefine
执行方式各块独立，可以并行必须按顺序串行
速度快慢（文档越多越慢）
token 消耗较少较多（每一步都要带上当前摘要）
上下文连贯性块与块之间互不知情，可能重复或遗漏关联每步都能看到之前的结论，连贯性好
弱点合并时可能丢掉某块的要点排在前面的文档影响更大
适合文档很多、追求速度希望每份文档的核心都体现在最终摘要里

摘要策略决策图

还有第三种最简单的策略叫 Stuff（直接塞）：内容不长，就整个放进一条提示词里。完整的选择流程如下：

小结

  • 内容超出上下文窗口（或虽然装得下但太贵）时，需要拆开处理。
  • Map-Reduce：切块 → 每块独立摘要（可并行）→ 合并。快、省，但块之间互不知情。
  • Refine：维护一份滚动摘要，每读一份文档修订一次。连贯，但只能串行、更费 token。
  • Stuff：装得下就直接塞，最简单。
  • 文档加载器把各种来源统一成 Document（正文 + 元数据），下游逻辑不必关心原始格式。
  • 链适合单向流动的数据处理；需要循环累积时，普通代码更清晰。
