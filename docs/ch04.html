第 4 章

构建研究摘要引擎

这一章做第一个「像样的」应用：你问一个问题，它自己上网搜索、抓取网页、逐页摘要，最后写出一份带引用来源的研究报告。 我们会写两遍 —— 先用最直白的顺序代码，再用 LCEL 链重写 —— 这样你能亲眼看到「链」到底带来了什么。

本章目标

  • 把一个模糊的需求拆成清晰的处理步骤
  • 实现网页搜索和网页抓取两个基础能力
  • 理解「查询改写」为什么能明显提升搜索质量
  • 让模型输出 JSON，并在代码里解析它
  • 用 LCEL 把多条子链组合成一条主链，并让它自动并行

从手工到自动

假设你想了解「西班牙小城阿斯托加有什么可看可玩的」。手工的做法是：打开搜索引擎 → 点开前几条结果 → 把每个网页的内容贴给 ChatGPT 让它总结 → 再让它把几份总结合成一篇报告。

每一步都不难，但全是体力活。研究摘要引擎就是把这套流程自动化：

四个基础函数

网页搜索

from langchain_community.utilities import DuckDuckGoSearchAPIWrapper
from typing import List

def web_search(web_query: str, num_results: int) -> List[str]:
    return [r["link"]
        for r in DuckDuckGoSearchAPIWrapper().results(web_query, num_results)]

// npm install duck-duck-scrape
import { DuckDuckGoSearch } from "@langchain/community/tools/duckduckgo_search";

export async function webSearch(webQuery: string, numResults: number): Promise<string[]> {
  const tool = new DuckDuckGoSearch({ maxResults: numResults });
  // 工具返回 JSON 字符串：[{ title, link, snippet }, ...]
  const results = JSON.parse(await tool.invoke(webQuery)) as { link: string }[];
  return results.map((r) => r.link);
}

// LangChain4j 没有 DuckDuckGo 集成，这里换用 Tavily（有免费额度，需要 TAVILY_API_KEY）。
// 依赖：langchain4j-web-search-engine-tavily
import dev.langchain4j.web.search.WebSearchEngine;
import dev.langchain4j.web.search.WebSearchRequest;
import dev.langchain4j.web.search.tavily.TavilyWebSearchEngine;

public class WebSearching {
    private static final WebSearchEngine ENGINE = TavilyWebSearchEngine.builder()
            .apiKey(System.getenv("TAVILY_API_KEY")).build();

    public static List<String> webSearch(String webQuery, int numResults) {
        return ENGINE.search(WebSearchRequest.builder()
                        .searchTerms(webQuery).maxResults(numResults).build())
                .results().stream()
                .map(r -> r.url().toString())
                .toList();
    }
}

网页抓取

下载 HTML，去掉所有标签，只留文字。带上浏览器的 User-Agent 请求头，否则不少网站会直接拒绝。

import requests
from bs4 import BeautifulSoup

def web_scrape(url: str) -> str:
    try:
        headers = {
            "User-Agent": ("Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
                           "AppleWebKit/537.36 (KHTML, like Gecko) "
                           "Chrome/124.0.0.0 Safari/537.36"),
            "Accept-Language": "en-US,en;q=0.9",
        }
        response = requests.get(url, headers=headers, timeout=15)

        if response.status_code == 200:
            soup = BeautifulSoup(response.text, "html.parser")
            return soup.get_text(separator=" ", strip=True)
        else:
            return f"Failed to retrieve the webpage: Status code {response.status_code}"
    except Exception as e:
        return f"Failed to retrieve the webpage: {e}"

// npm install cheerio
import * as cheerio from "cheerio";

export async function webScrape(url: string): Promise<string> {
  try {
    const response = await fetch(url, {
      headers: {
        "User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 " +
                      "(KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36",
        "Accept-Language": "en-US,en;q=0.9",
      },
      signal: AbortSignal.timeout(15_000),
    });
    if (!response.ok) {
      return `Failed to retrieve the webpage: Status code ${response.status}`;
    }
    const $ = cheerio.load(await response.text());
    $("script, style").remove();
    return $("body").text().replace(/\s+/g, " ").trim();
  } catch (e) {
    return `Failed to retrieve the webpage: ${e}`;
  }
}

// 依赖：org.jsoup:jsoup
import org.jsoup.Jsoup;

public class WebScraping {
    public static String webScrape(String url) {
        try {
            return Jsoup.connect(url)
                    .userAgent("Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 "
                             + "(KHTML, like Gecko) Chrome/124.0.0.0 Safari/537.36")
                    .header("Accept-Language", "en-US,en;q=0.9")
                    .timeout(15_000)
                    .get()
                    .text();                 // 去掉所有标签，只留文字
        } catch (Exception e) {
            return "Failed to retrieve the webpage: " + e.getMessage();
        }
    }
}
ⓘ 为什么失败时返回字符串而不是抛异常

一次研究要抓好几个网页，其中一两个超时或 403 很正常。如果抛异常，整个流程就中断了； 返回一段说明文字，后面的摘要步骤顶多得到一条没用的摘要，其余网页不受影响。这是「部分失败不该拖垮整体」的常见处理方式。

升级架构：先改写问题，再去搜索

v1 架构有个明显的弱点：直接拿用户的原话去搜。但人提问的方式和搜索引擎喜欢的关键词往往不一样， 而且一个问题常常包含多个方面，一次搜索覆盖不全。

改进办法是加两步「让 LLM 先想一想」：

  1. 选助手：判断问题属于哪个领域，选一个合适的「专家人设」（导游、金融分析师、体育评论员……）。
  2. 改写查询：让这位专家把用户问题改写成若干条更适合搜索引擎的查询。

四个提示词

完整文本在仓库的 ch04/prompts.py，这里只看每个提示词的关键设计。

① 选助手：用少样本示例 + JSON 输出

You are skilled at assigning a research question to the correct research assistant.
There are various research assistants available, each specialized in an area of expertise.
...
Examples:
Question: "Should I invest in Apple stocks?"
Response:
{{
    "assistant_type": "Financial analyst assistant",
    "assistant_instructions": "You are a seasoned finance analyst AI assistant. Your primary goal is ...",
    "user_question": {user_question}
}}
Question: "what are the most interesting sites in Tel Aviv?"
Response:
{{
    "assistant_type": "Tour guide assistant",
    "assistant_instructions": "You are a world-travelled AI tour guide assistant. Your main purpose is ...",
    "user_question": "{user_question}"
}}
...
Now that you have understood all the above, select the correct research assistant
for the following question.
Question: {user_question}
Response:

三个值得学的技巧：

  • 用例子示范输出格式（第 2 章的少样本学习）。模型看过几个 JSON 例子后，就会照着格式输出。
  • 双花括号 {{ }}：单花括号是模板占位符，想输出字面意义的花括号就得写两个。
  • 让输出带上 user_question：这样下一步只需要拿到这一个 JSON，就有了继续处理所需的全部信息。

② 改写查询

{assistant_instructions}

Write {num_search_queries} web search queries to gather as much information as possible
on the following question: {user_question}. Your objective is to write a report based on
the information you find.
You must respond with a list of queries such as query1, query2, query3 in the following format:
[
    {{"search_query": "query1", "user_question": "{user_question}" }},
    {{"search_query": "query2", "user_question": "{user_question}" }},
    {{"search_query": "query3", "user_question": "{user_question}" }}
]

第一行直接把上一步选出来的「助手人设」放进来 —— 一个提示词的输出成为下一个提示词的一部分，这就是「链」这个名字的由来。

③ 单页摘要 与 ④ 研究报告

# ③ 单页摘要
Read the following text:
Text: {search_result_text}
-----------
Using the above text, answer in short the following question.
Question: {search_query}
-----------
If you cannot answer the question above using the text provided above, then just summarize
the text. Include all factual information, numbers, stats etc if available.

# ④ 研究报告
You are an AI critical thinker research assistant. ...
Information:
--------
{research_summary}
--------
Using the above information, answer the following question or topic: "{user_question}"
in a detailed report -- ... a minimum of 1,200 words.
You must write the report with markdown syntax.
Write all used source urls at the end of the report, and make sure to not add duplicated sources ...

③ 不是泛泛地总结网页，而是针对搜索查询去提取答案，同时留了退路（答不出就做普通摘要）。 ④ 明确规定了篇幅、格式和「必须列出来源」。

版本一：顺序代码

先用最直白的方式实现：调模型、拿结果、拼下一个提示词、再调模型……对应仓库的 research_engine_seq.py。

NUM_SEARCH_QUERIES = 2
NUM_SEARCH_RESULTS_PER_QUERY = 3
RESULT_TEXT_MAX_CHARACTERS = 10000
question = 'What can I see and do in the Spanish town of Astorga?'

llm = get_llm()

assistant_selection_prompt = ASSISTANT_SELECTION_PROMPT_TEMPLATE.format(
    user_question=question)
assistant_instructions = llm.invoke(assistant_selection_prompt)
assistant_instructions_dict = to_obj(assistant_instructions.content)

# ② 改写成若干条搜索查询
web_search_prompt = WEB_SEARCH_PROMPT_TEMPLATE.format(
    assistant_instructions=assistant_instructions_dict['assistant_instructions'],
    num_search_queries=NUM_SEARCH_QUERIES,
    user_question=assistant_instructions_dict['user_question'])
web_search_queries = llm.invoke(web_search_prompt)
web_search_queries_list = to_obj(web_search_queries.content.replace('\n', ''))

# ③ 每条查询去搜索，把结果摊平成 [{search_query, result_url}, ...]
search_query_and_result_url_list = []
for wq in web_search_queries_list:
    for url in web_search(web_query=wq['search_query'],
                          num_results=NUM_SEARCH_RESULTS_PER_QUERY):
        search_query_and_result_url_list.append(
            {'search_query': wq['search_query'], 'result_url': url})

# ④ 抓取每个网页（只取前 10000 个字符），再逐个摘要
result_text_summary_list = []
for re in search_query_and_result_url_list:
    result_text = web_scrape(url=re['result_url'])[:RESULT_TEXT_MAX_CHARACTERS]
    summary_prompt = SUMMARY_PROMPT_TEMPLATE.format(
        search_result_text=result_text, search_query=re['search_query'])
    text_summary = llm.invoke(summary_prompt)
    result_text_summary_list.append(
        {'text_summary': text_summary.content, 'result_url': re['result_url']})

# ⑤ 合并摘要，生成报告
appended_result_summaries = '\n'.join(
    f'Source URL: {sr["result_url"]}\nSummary: {sr["text_summary"]}'
    for sr in result_text_summary_list)

research_report = llm.invoke(RESEARCH_REPORT_PROMPT_TEMPLATE.format(
    research_summary=appended_result_summaries, user_question=question))

print(research_report.content)

const NUM_SEARCH_QUERIES = 2;
const NUM_SEARCH_RESULTS_PER_QUERY = 3;
const RESULT_TEXT_MAX_CHARACTERS = 10000;
const question = "What can I see and do in the Spanish town of Astorga?";

const llm = getLlm();
const ask = async (prompt: string) => (await llm.invoke(prompt)).content as string;

// ① 选助手
const assistant = toObj(await ask(
  await ASSISTANT_SELECTION_PROMPT_TEMPLATE.format({ user_question: question })));

// ② 改写成若干条搜索查询
const queries: { search_query: string }[] = toObj(await ask(
  await WEB_SEARCH_PROMPT_TEMPLATE.format({
    assistant_instructions: assistant.assistant_instructions,
    num_search_queries: NUM_SEARCH_QUERIES,
    user_question: assistant.user_question,
  })));

// ③ 每条查询去搜索，摊平
const queryAndUrls: { search_query: string; result_url: string }[] = [];
for (const q of queries) {
  for (const url of await webSearch(q.search_query, NUM_SEARCH_RESULTS_PER_QUERY)) {
    queryAndUrls.push({ search_query: q.search_query, result_url: url });
  }
}

// ④ 抓取 + 逐个摘要
const summaries: string[] = [];
for (const item of queryAndUrls) {
  const text = (await webScrape(item.result_url)).slice(0, RESULT_TEXT_MAX_CHARACTERS);
  const summary = await ask(await SUMMARY_PROMPT_TEMPLATE.format({
    search_result_text: text, search_query: item.search_query }));
  summaries.push(`Source URL: ${item.result_url}\nSummary: ${summary}`);
}

// ⑤ 生成报告
const report = await ask(await RESEARCH_REPORT_PROMPT_TEMPLATE.format({
  research_summary: summaries.join("\n"), user_question: question }));

console.log(report);

它能跑，也好懂。但有两个问题：

问题一：慢

6 个网页是一个接一个抓取和摘要的。每次模型调用几秒钟，加起来就是半分钟以上 —— 而它们之间明明没有任何依赖，完全可以同时进行。

问题二：各步骤纠缠在一起

所有逻辑挤在一个脚本里，想单独测试「改写查询」这一步，或者把「摘要」步骤换成另一种实现，都得动整个文件。

版本二：用 LCEL 重写

思路是把流程拆成五条各自能独立运行和测试的小链，再像搭积木一样组合起来：

链 1：选助手

from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser

assistant_instructions_chain = (
    {'user_question': RunnablePassthrough()}     # 字符串 → {'user_question': 字符串}
    | ASSISTANT_SELECTION_PROMPT_TEMPLATE
    | get_llm() | StrOutputParser() | to_obj     # 消息 → 字符串 → 字典
)

# 试运行
print(assistant_instructions_chain.invoke(
    'What can I see and do in the Spanish town of Astorga?'))
# {'assistant_type': 'Tour guide assistant', 'assistant_instructions': '...', 'user_question': '...'}

import { StringOutputParser } from "@langchain/core/output_parsers";

export const assistantInstructionsChain = RunnableSequence.from([
  { user_question: new RunnablePassthrough() },   // 字符串 → { user_question: 字符串 }
  ASSISTANT_SELECTION_PROMPT_TEMPLATE,
  getLlm(),
  new StringOutputParser(),
  RunnableLambda.from(toObj),                     // 字符串 → 对象

// 试运行

💡 RunnablePassthrough 与「字典即并行」

RunnablePassthrough() 的意思是「输入是什么就原样传下去」。 而在 LCEL 里，一个字典会被自动当作 RunnableParallel：它的每个值各自处理同一份输入，结果按键组装成新字典。 所以 {'user_question': RunnablePassthrough()} 就是「把输入字符串包成一个带 user_question 键的字典」。

record SearchResult(String resultUrl, String searchQuery) {}

static List<SearchResult> searchResultUrls(SearchQuery q) {
    return WebSearching.webSearch(q.searchQuery(), 3).stream()
            .map(url -> new SearchResult(url, q.searchQuery()))
            .toList();
}

留意一个细节：每一步的输出都把 user_question 继续往下带。链是一根单向的管子，后面的步骤拿不到更早的数据，除非有人一路把它传下来。这是 LCEL 里常见的小麻烦，也是第 5 章引入「共享状态」的动机之一。

链 4：抓取并摘要一个网页

search_result_text_and_summary_chain = (
    RunnableLambda(lambda x: {                         # 第一步：抓取网页
        'search_result_text':
            web_scrape(url=x['result_url'])[:RESULT_TEXT_MAX_CHARACTERS],

        'user_question': x['user_question']})

import { RunnableParallel } from "@langchain/core/runnables";

const RESULT_TEXT_MAX_CHARACTERS = 10000;

export const searchResultTextAndSummaryChain = RunnableSequence.from([
  RunnableLambda.from(async (x: any) => ({               // 第一步：抓取网页
    search_result_text: (await webScrape(x.result_url)).slice(0, RESULT_TEXT_MAX_CHARACTERS),
    result_url: x.result_url,
    search_query: x.search_query,
    user_question: x.user_question,
  })),
  RunnableParallel.from({                                // 第二步：三件事同时做
    text_summary: SUMMARY_PROMPT_TEMPLATE.pipe(getLlm()).pipe(new StringOutputParser()),
    result_url: (x: any) => x.result_url,
    user_question: (x: any) => x.user_question,
  }),
  RunnableLambda.from((x: any) => ({                     // 第三步：整理成「来源 + 摘要」
    summary: `Source Url: ${x.result_url}\nSummary: ${x.text_summary}`,
    user_question: x.user_question,
  })),
]);

static String scrapeAndSummarize(Researcher ai, SearchResult r) {
    String text = WebScraping.webScrape(r.resultUrl());
    text = text.substring(0, Math.min(text.length(), 10_000));
    String summary = ai.summarize(text, r.searchQuery());
    return "Source Url: " + r.resultUrl() + "\nSummary: " + summary;
}

// Java 没有 .map() 管道，用 CompletableFuture 表达同样的「两层并行」。
static String webResearch(Researcher ai, String question) {
    AssistantInfo assistant = ai.selectAssistant(question);
    List<SearchQuery> queries = ai.writeQueries(assistant.assistantInstructions(), 2, question);

    var executor = Executors.newVirtualThreadPerTaskExecutor();     // Java 21 虚拟线程

    List<CompletableFuture<String>> perQuery = queries.stream()
            .map(q -> CompletableFuture.supplyAsync(() -> {         // 每条查询并行
                var perUrl = searchResultUrls(q).stream()
                        .map(r -> CompletableFuture.supplyAsync(    // 每个 URL 并行
                                () -> scrapeAndSummarize(ai, r), executor))
                        .toList();
                return perUrl.stream().map(CompletableFuture::join)
                        .collect(Collectors.joining("\n"));
            }, executor))
            .toList();

    String researchSummary = perQuery.stream().map(CompletableFuture::join)
            .collect(Collectors.joining("\n\n"));

    return ai.writeReport(researchSummary, question);
}

快了多少

🔑 LCEL 带来的三个实际好处
  • 并行是免费的：加一个 .map() 就行，不用自己管线程或 asyncio。
  • 每条链都能单独测试：仓库里的 chain_try_*.py 就是逐条验证的脚本，出问题时很容易定位到是哪一环。
  • 积木可替换：想换个搜索引擎，只动链 3；想换个摘要提示词，只动链 4。

这个引擎还缺什么

流程是一条直线：搜到什么就用什么。如果搜回来的网页大多不相关呢？它还是会硬着头皮写一篇报告。 我们希望它能检查搜索结果的质量，不行就换个搜法再来一遍 —— 这需要「回头」的能力，而单向的链做不到。 下一章用 LangGraph 来解决。

小结

  • 研究摘要引擎 = 搜索 + 抓取 + 逐页摘要 + 写报告，本质上是以网页为数据源的 Map-Reduce。
  • 在搜索前加入「选助手」和「查询改写」两步，能显著改善搜到的内容。
  • 想让模型输出结构化数据：在提示词里用例子示范 JSON 格式，再用解析器转成对象（Java 里直接声明返回类型）。
  • 顺序代码直观但慢，且各步骤耦合在一起。
  • LCEL 把流程拆成可独立测试的小链；.map() 和 RunnableParallel 让并行几乎不费力气。
  • 链是单向的：数据要一路往下传，流程不能回头 —— 这是它的局限。
