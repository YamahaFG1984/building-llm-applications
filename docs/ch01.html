先用一句话说清 LLM

大语言模型（Large Language Model，LLM）是一个文字接龙机器：你给它一段文字（叫提示词，prompt）， 它根据训练时读过的海量文本，一个词一个词地预测「接下来最可能出现什么」。

神奇的地方在于：只要接龙接得足够好，它就表现得像是会总结、会翻译、会写代码、会推理。 但它也有三个天生的短板，后面每一章几乎都在想办法弥补它们：

📅

知识有截止日期

它只知道训练数据里的东西，不知道昨天的新闻，更不知道你公司的内部文档。

📏

一次读不了太多

提示词加回答的总长度有上限，叫上下文窗口。一整本书塞不进去。

✋

只会说，不会做

它输出的永远是文字。查数据库、调接口、订酒店，都得靠外面的程序替它动手。

ⓘ 什么是 token

模型处理文字的最小单位不是字也不是词，而是 token（词元）。英文里一个 token 大约是 3/4 个单词， 中文里一个汉字通常是 1–2 个 token。上下文窗口的大小、API 的价格，都是按 token 算的。

三类 LLM 应用

引擎：一问一答的后台服务

引擎（engine）是最简单的形态：接收一个请求，内部跑一串固定步骤，返回一个结果，然后就结束了，不记得上一次发生过什么。 典型例子是摘要引擎和问答引擎。它通常藏在一个 REST 接口后面，被别的系统调用。

聊天机器人：有记忆的多轮对话

聊天机器人（chatbot）多了两样东西：对话和记忆。 你说「帮我总结《战争与和平》」，它给了 1000 字；你接着说「太长了，两三句话就行」—— 它得记得「太长了」说的是刚才那份摘要。

这里有个初学者常有的误解：模型自己并不记得上一轮。所谓「记忆」，是应用程序把之前的对话原样再发一遍。

智能体：自己决定下一步做什么

AI 智能体（agent）又往前走了一大步：它手里有一组工具（函数、API、数据库查询……）， 每一步都先问 LLM「现在该用哪个工具、参数是什么」，执行完再把结果交回给 LLM，如此循环，直到任务完成。

书里的例子是旅行社的度假套餐助手：用户说「帮我安排七月去康沃尔的一周行程」， 智能体自己去查航班、酒店、租车、天气预报和内部优惠数据库，最后拼成一份完整方案。

🔑 三者的本质区别

引擎的流程是程序员写死的；聊天机器人多了记忆； 智能体则把「下一步做什么」的决定权交给了 LLM。自主程度越高，能做的事越多，也越难预测和调试 —— 所以高风险场景（金融、医疗）通常会在关键步骤加上人工确认（human-in-the-loop）。

LangChain 帮我们做了什么

理论上，只用 HTTP 请求就能调用 LLM。但真做起应用来，你会反复写同样的东西： 读各种格式的文件、把长文切成小块、拼提示词、解析模型输出、换一家模型供应商就要改一遍代码……

LangChain 就是把这些重复劳动抽象成了一套可以互相拼接的标准积木。它有三个核心卖点：

  • 统一接口：OpenAI、Gemini、Claude、本地模型……换模型只改一行。
  • 现成组件：几十种文档加载器、切分器、向量库适配器，开箱即用。
  • 可组合：每块积木都实现同一个 Runnable 接口，可以像管道一样串起来。

整体架构：一条数据流水线

让模型懂你的业务：三种手段

通用模型不知道你公司的产品手册，也不知道你想要的回答风格。有三种办法补上这一课，成本从低到高：

提示词工程（Prompt Engineering）
精心设计输入，让模型明白任务。常用技巧是上下文学习（in-context learning）：在提示词里放几个例子，模型就能照猫画虎，不需要任何训练。第 2 章专门讲。
RAG（Retrieval-Augmented Generation，检索增强生成）
提问时先从你自己的资料库里检索相关内容，塞进提示词，让模型「看着资料回答」。它解决了知识截止和私有数据两个问题，还能减少模型瞎编（幻觉）。第 6–10 章专门讲。
微调（Fine-tuning）
用专门的数据集继续训练模型，让它把领域知识和风格「记进脑子里」。效果扎实，但准备数据和训练都很贵。医学、法律、金融等高度专业的领域才值得。本教程不涉及微调。
💡 实用的选择顺序

先试提示词工程 → 不够再加 RAG → 还不够才考虑微调。 研究表明，对于冷门知识，RAG 的效果常常比微调更好，而且数据一变只需要更新索引，不用重新训练。

选哪个模型

没有「最好的模型」，只有「最适合这个任务的模型」。核心是三者之间的权衡：

除了这个三角，还要看：

  • 上下文窗口：要处理的文档有多长？常见 API 是 12.8 万到 25.6 万 token，少数模型能到百万级。
  • 多语言能力：要处理中文或小语种时，不同模型差距很大。
  • 指令型 vs 推理型：步骤明确的任务用指令型模型；需要它自己琢磨「怎么做」的任务用推理型（更慢更贵）。
  • 开源 vs 闭源：开源模型（Llama、Mistral、Qwen）可以自己部署，数据不出门；闭源 API 上手快，效果通常领先。

更细的对比表和本地部署方法见附录。

动手：第一条链

概念够多了，写点代码。下面四步对应仓库里的 ch01/01-langchain_examples.ipynb。

第一步：让模型接龙

from langchain_openai import ChatOpenAI
import getpass

OPENAI_API_KEY = getpass.getpass('Enter your OPENAI_API_KEY')

llm = ChatOpenAI(openai_api_key=OPENAI_API_KEY,
                 model_name="gpt-5-nano")

response = llm.invoke("It's a hot day, I would like to go to the...")
print(response.content)
# 可能的输出：...beach to cool off in the water.

import { ChatOpenAI } from "@langchain/openai";

// 不传 apiKey 时自动读取环境变量 OPENAI_API_KEY
const llm = new ChatOpenAI({ model: "gpt-5-nano" });

const response = await llm.invoke("It's a hot day, I would like to go to the...");
console.log(response.content);
// 可能的输出：...beach to cool off in the water.

import dev.langchain4j.model.chat.ChatModel;
import dev.langchain4j.model.openai.OpenAiChatModel;

ChatModel llm = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-5-nano")
        .build();

String answer = llm.chat("It's a hot day, I would like to go to the...");
System.out.println(answer);
// 可能的输出：...beach to cool off in the water.

注意返回值：Python 和 TypeScript 里得到的是一个消息对象（AIMessage），正文在 .content 里， 另外还带着 token 用量等元数据；LangChain4j 的 chat(String) 是个便捷方法，直接返回字符串。

第三步：提示词模板

真实应用里，提示词的大部分文字是固定的，只有少数几处会变。把变化的部分挖成占位符，就是提示词模板 —— 和你熟悉的字符串模板没有本质区别，只是 LangChain 把它做成了可以接进流水线的积木。 

from langchain_core.prompts import PromptTemplate

segovia_aqueduct_text = """The Aqueduct of Segovia is a Roman aqueduct
in Segovia, Spain. It was built around the first century AD ..."""   # 原文较长，此处省略

prompt_template = PromptTemplate.from_template(
    """You are an experienced copywriter. Write a {num_words} words summary of
the following text, using a {tone} tone: {text}""")

prompt_input = prompt_template.format(
    text=segovia_aqueduct_text,
    num_words=20,
    tone="knowledgeable and engaging")

response = llm.invoke(prompt_input)
print(response.content)

import { PromptTemplate } from "@langchain/core/prompts";

const segoviaAqueductText = `The Aqueduct of Segovia is a Roman aqueduct
in Segovia, Spain. It was built around the first century AD ...`;   // 原文较长，此处省略

const promptTemplate = PromptTemplate.fromTemplate(
  `You are an experienced copywriter. Write a {num_words} words summary of
the following text, using a {tone} tone: {text}`);

const promptInput = await promptTemplate.format({
  text: segoviaAqueductText,
  num_words: 20,
  tone: "knowledgeable and engaging",
});

const response = await llm.invoke(promptInput);
console.log(response.content);

import dev.langchain4j.model.input.PromptTemplate;
import java.util.Map;

String segoviaAqueductText = """
        The Aqueduct of Segovia is a Roman aqueduct
        in Segovia, Spain. It was built around the first century AD ...""";   // 原文较长，此处省略

// 注意：LangChain4j 的占位符是双花括号 {{name}}
PromptTemplate promptTemplate = PromptTemplate.from("""
        You are an experienced copywriter. Write a {{num_words}} words summary of
        the following text, using a {{tone}} tone: {{text}}""");

String promptInput = promptTemplate.apply(Map.of(
        "text", segoviaAqueductText,
        "num_words", 20,
        "tone", "knowledgeable and engaging")).text();

System.out.println(llm.chat(promptInput));

第四步：把模板和模型串成链

上一步里我们手动做了两件事：格式化模板、调用模型。LangChain 允许把它们接成一根管子，一次调用走完。 这种写法叫 LCEL（LangChain Expression Language）。 

chain = prompt_template | llm        # 竖线 | 就是「接管子」

response = chain.invoke({
    "text": segovia_aqueduct_text,
    "num_words": 20,
    "tone": "knowledgeable and engaging"})
print(response.content)

// JavaScript 没法重载 | 运算符，所以用 .pipe()
const chain = promptTemplate.pipe(llm);

const response = await chain.invoke({
  text: segoviaAqueductText,
  num_words: 20,
  tone: "knowledgeable and engaging",
});
console.log(response.content);

import dev.langchain4j.service.AiServices;
import dev.langchain4j.service.UserMessage;
import dev.langchain4j.service.V;

// LangChain4j 没有 | 管道。它的惯用法是「AI Service」：
// 你只声明一个接口，框架在运行时生成实现 —— 模板 + 调模型 + 解析输出一步到位。
interface Copywriter {
    @UserMessage("""
            You are an experienced copywriter. Write a {{num_words}} words summary of
            the following text, using a {{tone}} tone: {{text}}""")
    String summarize(@V("text") String text,
                     @V("num_words") int numWords,
                     @V("tone") String tone);
}

Copywriter chain = AiServices.create(Copywriter.class, llm);

System.out.println(chain.summarize(segoviaAqueductText, 20, "knowledgeable and engaging"));
🔬 为什么「链」值得专门发明一个语法

因为所有积木都实现了同一个接口（invoke / batch / stream）， 串起来的链自己也是一块积木，可以继续被串进更大的链里。 而且框架知道了整条流水线的结构，就能自动帮你做并行、流式输出、重试和链路追踪 —— 第 4 章会看到这一点有多省事。

小结

  • LLM 是文字接龙机器，有知识截止、上下文窗口有限、不能动手三个短板。
  • LLM 应用有三种形态：引擎（一问一答）、聊天机器人（多轮 + 记忆）、智能体（自己选工具、自己决定下一步）。
  • LangChain 提供统一接口、现成组件和可组合的链；LangGraph 在它之上处理带分支和循环的复杂流程。
  • 让模型适应业务的三种手段：提示词工程 → RAG → 微调，成本依次升高。
  • 选模型就是在准确度、速度、成本之间找平衡；一个系统里混用多档模型很常见。
  • 提示词模板 + 模型 = 最短的一条链。
