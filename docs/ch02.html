第 2 章

用代码执行提示词

在聊天窗口里打字和在程序里调用模型，背后是同一件事：发一段提示词，收一段回答。 这一章先把这层窗户纸捅破，然后系统地学习怎么写提示词才能得到想要的结果 —— 这是后面所有章节的基本功。

本章目标

  • 不借助任何框架，直接调用 OpenAI 的 API
  • 理解 system / user / assistant 三种消息角色
  • 用模板管理提示词，而不是到处拼字符串
  • 认识六类常见提示词任务
  • 掌握少样本学习（few-shot）和思维链（Chain of Thought）
  • 记住一份好提示词的八个组成部分

不用框架，直接调 API

先看看「裸」的调用长什么样。理解了这一层，你就知道 LangChain 封装掉的是什么，出问题时也知道该往哪里查。 

from openai import OpenAI          # pip install openai

三种消息角色

角色谁在说话用来做什么
system开发者给模型定规矩：你是谁、该怎么回答、不能做什么。用户通常看不到它。
user（human）用户用户的提问或指令。
assistant（ai）模型模型之前的回答。多轮对话时要把它们放回 messages 里。

同一件事，用 LangChain 写

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(openai_api_key=OPENAI_API_KEY, model_name="gpt-5-nano")

response = llm.invoke(prompt_input)
print(response.content)

import { ChatOpenAI } from "@langchain/openai";

const llm = new ChatOpenAI({ model: "gpt-5-nano" });

const response = await llm.invoke(promptInput);
console.log(response.content);

import dev.langchain4j.model.openai.OpenAiChatModel;

var llm = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY"))
        .modelName("gpt-5-nano")
        .build();

代码短了，但更重要的是：把 ChatOpenAI 换成 ChatAnthropic 或 ChatOllama， 下面的代码一行都不用改。这就是统一接口的价值。

最朴素的做法：一个函数

    return (f"You are an experienced copywriter. Write a {num_words} words "
            f"summary of the following text, using a {tone} tone: {text}")

input_prompt = generate_text_summary_prompt(

  return `You are an experienced copywriter. Write a ${numWords} words ` +
         `summary of the following text, using a ${tone} tone: ${text}`;

const inputPrompt = generateTextSummaryPrompt(

String inputPrompt = generateTextSummaryPrompt(

这完全能用。那为什么还需要框架提供的 PromptTemplate？因为它是一块标准积木： 能接进链里、能被 LangSmith 追踪、能被序列化保存、能自动校验「你是不是漏填了某个变量」。 用法第 1 章已经见过：

    text=segovia_aqueduct_text, num_words=20, tone="knowledgeable and engaging")

六类常见的提示词任务

绝大多数提示词都可以归到下面六类里。认识它们，是为了在遇到新需求时能快速对号入座。

类型让模型做什么提示词示例
文本分类把文本归入预先给定的类别把下面这条新闻归为「体育 / 财经 / 科技 / 娱乐」之一：……
情感分析判断语气是正面、负面还是中性这条评价的情绪是正面还是负面？「等了一小时才上菜」
文本摘要压缩长文本，保留要点用三句话总结下面这篇文章：……
文本撰写按要求写新内容写一封 100 字的邮件，提醒同事注意钓鱼攻击，语气友好
问答根据给定材料回答问题阅读下面的文字后回答：塞哥维亚水道桥有多少个拱？
推理做逻辑或数学推导我有 5 个苹果，吃了 2 个又买了 4 个，现在有几个？请一步步算。

前五类，现在的模型基本「说清楚就能做好」。最容易翻车的是推理，所以下面单独展开。

教模型推理：从零样本到少样本

假设我们发明了一个模型肯定没见过的规则，看看怎么把它教会：

ⓘ Abra Kadabra 规则

一个数能被 5 整除叫 Abra，能被 7 整除叫 Kadabra， 同时能被 5 和 7 整除叫 Abra Kadabra，都不能则是 None。

手写的少样本提示词

Classify the following numbers as Abra, Kadabra or Abra Kadabra:

3, 4, 5, 7, 8, 10, 11, 13, 35

Examples:
6 // not divisible by 5, not divisible by 7 // None
15 // divisible by 5, not divisible by 7 // Abra
12 // not divisible by 5, not divisible by 7 // None
21 // not divisible by 5, divisible by 7 // Kadabra
70 // divisible by 5, divisible by 7 // Abra Kadabra

每个例子有三段：输入 // 推理过程 // 结论。中间那段推理过程正是关键 —— 没有它，模型只能看到「15 是 Abra」，猜不出为什么。

用 FewShotPromptTemplate 管理例子

例子多了以后，硬编码在字符串里不好维护。把例子抽成数据，把「一个例子长什么样」抽成小模板，再由框架拼起来： 

from langchain_core.prompts.few_shot import FewShotPromptTemplate
from langchain_core.prompts.prompt import PromptTemplate

examples = [
  {"number": 6,  "reasoning": "not divisible by 5 nor by 7", "result": "None"},
  {"number": 15, "reasoning": "divisible by 5 but not by 7", "result": "Abra"},
  {"number": 12, "reasoning": "not divisible by 5 nor by 7", "result": "None"},
  {"number": 21, "reasoning": "divisible by 7 but not by 5", "result": "Kadabra"},
  {"number": 70, "reasoning": "divisible by 5 and by 7",     "result": "Abra Kadabra"},
]

example_prompt = PromptTemplate(
    input_variables=["number", "reasoning", "result"],
    template="{number} \\ {reasoning} \\ {result}")

few_shot_prompt = FewShotPromptTemplate(
    examples=examples,
    example_prompt=example_prompt,
    suffix="Classify the following numbers as Abra, Kadabra or Abra Kadabra: "
           "{comma_delimited_input_numbers}",
    input_variables=["comma_delimited_input_numbers"])

prompt_input = few_shot_prompt.format(
    comma_delimited_input_numbers="3, 4, 5, 7, 8, 10, 11, 13, 35.")

llm = ChatOpenAI(openai_api_key=OPENAI_API_KEY, model_name="gpt-5-mini")
print(llm.invoke(prompt_input).content)

import { FewShotPromptTemplate, PromptTemplate } from "@langchain/core/prompts";
import { ChatOpenAI } from "@langchain/openai";

const examples = [
  { number: "6",  reasoning: "not divisible by 5 nor by 7", result: "None" },
  { number: "15", reasoning: "divisible by 5 but not by 7", result: "Abra" },
  { number: "12", reasoning: "not divisible by 5 nor by 7", result: "None" },
  { number: "21", reasoning: "divisible by 7 but not by 5", result: "Kadabra" },
  { number: "70", reasoning: "divisible by 5 and by 7",     result: "Abra Kadabra" },
];

const examplePrompt = PromptTemplate.fromTemplate("{number} \\ {reasoning} \\ {result}");

const fewShotPrompt = new FewShotPromptTemplate({
  examples,
  examplePrompt,
  suffix: "Classify the following numbers as Abra, Kadabra or Abra Kadabra: " +
          "{comma_delimited_input_numbers}",
  inputVariables: ["comma_delimited_input_numbers"],
});

  comma_delimited_input_numbers: "3, 4, 5, 7, 8, 10, 11, 13, 35.",
});

const llm = new ChatOpenAI({ model: "gpt-5-mini" });
console.log((await llm.invoke(promptInput)).content);

// LangChain4j 没有专门的 FewShotPromptTemplate —— 也不需要，
// 「例子是数据、模板是格式」这个思路用几行 Java 就能表达。
import dev.langchain4j.model.input.PromptTemplate;
import java.util.*;
import java.util.stream.Collectors;

record Example(int number, String reasoning, String result) {}

List<Example> examples = List.of(
        new Example(6,  "not divisible by 5 nor by 7", "None"),
        new Example(15, "divisible by 5 but not by 7", "Abra"),
        new Example(12, "not divisible by 5 nor by 7", "None"),
        new Example(21, "divisible by 7 but not by 5", "Kadabra"),
        new Example(70, "divisible by 5 and by 7",     "Abra Kadabra"));

PromptTemplate examplePrompt = PromptTemplate.from("{{number}} \\ {{reasoning}} \\ {{result}}");

String examplesText = examples.stream()
        .map(e -> examplePrompt.apply(Map.of(
                "number", e.number(), "reasoning", e.reasoning(), "result", e.result())).text())
        .collect(Collectors.joining("\n\n"));

PromptTemplate fewShotPrompt = PromptTemplate.from("""
        {{examples}}

        Classify the following numbers as Abra, Kadabra or Abra Kadabra: {{numbers}}""");

String promptInput = fewShotPrompt.apply(Map.of(
        "examples", examplesText,
        "numbers", "3, 4, 5, 7, 8, 10, 11, 13, 35.")).text();

var llm = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY")).modelName("gpt-5-mini").build();
System.out.println(llm.chat(promptInput));

另外两招：给步骤、让它「想出声」

给出步骤（Providing steps）
对下面每个数字，按这些步骤处理：
1. 检查能否被 5 整除
2. 检查能否被 7 整除
3. 都能 → Abra Kadabra
   只能被 5 → Abra
   只能被 7 → Kadabra
   都不能 → None
思维链（Chain of Thought）
……（规则说明）……

请一步一步地思考，
先写出你对每个数字的
推理过程，
最后再给出结论。
🔬 为什么「一步一步想」会有用

模型是一个词一个词往外写的，写后面的词时能「看到」自己前面写了什么。 如果它先把推理过程写出来，这些中间结论就成了后续生成的依据；如果直接让它蹦答案，它就只能凭直觉猜。 现在的推理型模型（比如 GPT-5 Thinking）把这个过程内置了：它会在给出答案前先在内部「打草稿」，所以对它们不必再手动加这句话。

技巧做法适合什么时候
零样本只给指令任务常见、模型本来就会
单样本 / 双样本给 1–2 个例子主要想示范输出格式
少样本给一组覆盖各种情况的例子规则是你自定义的、模型没见过
给出步骤把处理流程一条条写出来你清楚地知道该怎么做
思维链要求先推理再回答多步计算或逻辑推导

一份好提示词的结构

把前面的经验合在一起，就得到一份通用的检查清单。不是每一项都必须有，但写提示词时可以对着过一遍：

一个把多数零件都用上的例子：

PERSONA  You're an experienced Large Language Model (LLM) developer and renowned speaker.
CONTEXT  You've been invited to give a keynote speech for a LLM event.
INSTRUCTION  Write the punch lines for the speech.
INPUT  Include the following facts:
  - LLMs have become mainstream with the launch of ChatGPT in November 2022
  - many popular LLMs and LLM based chatbots have been launched since then
  - LLMs becoming as popular as search engines
  - many companies want to integrate LLMs in their applications
TONE  Use a witty but entertaining tone.
OUTPUT FORMAT  Present the text in two paragraphs of 5 lines each.

更稳妥的写法：用 XML 标签分段

OpenAI 和 Anthropic 的官方提示词指南都推荐用类似 XML 的标签把各部分包起来。 这样模型不容易把「要处理的材料」误当成「要执行的指令」—— 当输入里包含用户提供的、内容不可控的文本时尤其重要。 

<Persona>
You're an experienced Large Language Model (LLM) developer and renowned speaker.
</Persona>
<Context>
You've been invited to give a keynote speech for a LLM event.
</Context>
<Instruction>
Write the punch lines for the speech.
</Instruction>
<Input>
Include the following facts: ...
</Input>
<Tone>
Use a witty but entertaining tone.
</Tone>
<OutputFormat>
Present the text in two paragraphs of 5 lines each.
</OutputFormat>
💡 不必每一段都起名字

研究发现给提示词各部分显式命名通常能改善结果，但模型一般也能自己看出每段文字的用途。 实践中常见的做法是只给关键部分加标签（比如 Question、Examples、Context），其余的自然书写。 多试几种写法，以实际效果为准。

小结

  • 调用 LLM 就是发一个带 messages 列表的 HTTP 请求；消息有 system、user、assistant 三种角色。
  • LangChain（及 LangChain.js、LangChain4j）把各家模型包成统一接口，换模型不用改业务代码。
  • 提示词模板把「固定文字」和「可变参数」分开，是可以接进链里的标准积木。
  • 常见任务有六类：分类、情感分析、摘要、撰写、问答、推理。
  • 教模型新规则靠上下文学习：给例子（few-shot）、给步骤、让它先推理再回答（CoT）。
  • 提示词八要素：角色、背景、指令、输入、步骤、语气、输出格式、示例；用 XML 标签分段更稳。

动手练习

  1. 先用零样本让模型给 3, 4, 5, 7, 8, 10, 11, 13, 35 分类，记录它错了几个；再用少样本版本跑一次，对比结果。
  2. 把少样本例子里的 reasoning 字段删掉，只留数字和结论，准确率有变化吗？
  3. 用八要素清单给自己写一个提示词：让模型以「耐心的编程老师」的身份，向零基础的人解释什么是 API，输出为三个小标题加要点列表。
  4. 把第 3 题的提示词改写成 XML 标签形式，对比两个版本的输出。
