第 14 章

走向生产：记忆与护栏

我们的旅行助手已经很能干了，但离「敢给真实用户用」还差两样东西： 它记不住上一句话说了什么，也管不住自己 —— 你问它怎么炒股，它也会认真作答。 这一章补上记忆和护栏，然后看看通往生产的路上还有哪些功课。

本章目标

  • 分清短期记忆和长期记忆
  • 用 LangGraph 的检查点（checkpointer）和 thread_id 实现多轮对话
  • 查看状态历史，并把对话「倒带」到过去的某个时刻
  • 在路由层和智能体层分别加上输入护栏
  • 了解上线前还需要考虑的事：长期记忆、人工介入、输出护栏、评估、部署

记忆的种类

记忆类型范围保存多久旅行助手的例子难点
短期记忆一个用户的一次会话会话结束为止追问天气时记得「同一个镇」指哪儿会话一关就没了
长期记忆（用户级）一个用户的多次会话几周、几个月、几年记得用户偏爱的目的地和住宿类型隐私合规；管理持久化的数据
长期记忆（应用级）所有用户、所有会话持续存在康沃尔的活动日历、景点的季节性开放时间保持数据新鲜，避免过时或错误的信息

本章实现短期记忆。先看没有它时会怎样：

You: What's the weather like in Penzance?
Assistant: It's sunny and 24°C in Penzance.

You: Are there any hotels available in the same town?
Assistant: Could you tell me which town you mean?        ← 它已经不记得 Penzance 了

原因在聊天循环里：每一轮都用一个只含当前这句话的全新状态去调用图。上一轮的消息列表在 invoke 返回后就被丢掉了。

检查点：让图记住状态

第 7 章我们手动维护过一个消息历史对象。LangGraph 有更系统的做法：检查点（checkpoint）。 给图配一个检查点保存器（checkpointer）后，图每执行完一步，就自动把完整的状态存一份快照。

两个关键概念：

  • 线程（thread）：一场连续的对话，用 thread_id 标识。同一个 thread_id 的多次调用共享状态；不同的 thread_id 完全隔离 —— 所以它天然支持多用户。
  • 检查点（checkpoint）：某一步执行完后的状态快照。一个线程里有一串按时间排列的检查点。

ⓘ 为什么这次的状态能跨智能体共享

第一轮走的是旅行信息智能体，第二轮走的是住宿预订智能体 —— 两个不同的子图。 但它们读写的是同一个父图状态里的 messages，而检查点保存的正是这份状态。 所以预订智能体能看到信息智能体之前说过的话。

⚠ InMemorySaver 只适合开发

它把快照存在进程内存里：重启即丢失，也无法在多个服务实例之间共享。 生产环境换成持久化的保存器 —— SqliteSaver（单机）或 PostgresSaver（多实例）。 接口完全一样，只改初始化那一行。另外，消息只增不减，长对话需要裁剪或摘要（第 7 章讨论过）。

🐛

调试

智能体在第 5 步走偏了？直接查看第 4 步结束时的状态，而不用把整个对话重跑一遍。

🔀

分叉重试

回到某个检查点，修改状态（比如换个说法），从那里走出一条新的分支，对比两种结果。

⏸

断点续跑

图执行到一半被中断（崩溃，或在等人工审批），可以从最后一个检查点恢复，而不是从头来过。

护栏：让助手待在该待的地方

不加约束的助手什么都会答：写代码、给医疗建议、评论政治。这既浪费钱，也可能带来法律和品牌风险。 护栏（guardrails）是在模型周围设置的检查点，把不该处理的请求拦下来，把不该输出的内容挡回去。

我们在两个层级各加一道输入护栏：

第一道：路由层第二道：智能体层
规则只接受旅行相关的问题只接受关于康沃尔的旅行问题
位置路由节点里，分发之前每个 ReAct 智能体内部，每次调用模型之前
拦下后直接返回固定的拒绝语，跳到 END给模型注入一条「请礼貌拒绝」的指令
拦什么「帮我写个排序算法」「巴黎有什么好玩的？」

第一道：路由层护栏

用一个分类器（就是一次带结构化输出的 LLM 调用）判断问题是否与旅行有关。不相关就走一条新的「快速出口」：

from langchain_core.messages import AIMessage

class GuardrailDecision(BaseModel):
    is_travel: bool = Field(..., description=(
        "True if the user question is about travel information: destinations, attractions, "
        "lodging (hotels/BnBs), prices, availability, or weather in Cornwall/England."))
    reason: str = Field(..., description="Brief justification for the decision.")

GUARDRAIL_SYSTEM_PROMPT = (
    "You are a strict classifier. Given the user's last message, respond with whether it is "
    "travel-related. Travel-related queries include destinations, attractions, lodging "
    "(hotels/BnBs), room availability, prices, or weather in Cornwall/England.")

llm_guardrail = llm_model.with_structured_output(GuardrailDecision)

def router_agent_node(state: AgentState) -> Command:
    last_msg = state["messages"][-1] if state["messages"] else None
    if isinstance(last_msg, HumanMessage):
        user_input = last_msg.content

        # ① 护栏：先判断是不是旅行相关
        decision = llm_guardrail.invoke([
            SystemMessage(content=GUARDRAIL_SYSTEM_PROMPT),
            HumanMessage(content=user_input)])

        if not decision.is_travel:
            refusal_text = (
                "Sorry, I can only help with travel-related questions (destinations, "
                "attractions, lodging, prices, availability, or weather in Cornwall/England). "
                "Please rephrase your request to be travel-related.")
            return Command(                                      # 写入拒绝语，跳到快速出口
                update={"messages": [AIMessage(content=refusal_text)]},
                goto="guardrail_refusal")

        # ② 通过护栏后，照常路由
        router_response = llm_router.invoke([
            SystemMessage(content=ROUTER_SYSTEM_PROMPT),
            HumanMessage(content=user_input)])
        return Command(goto=router_response.agent.value)

    return Command(goto=AgentType.travel_info_agent.value)

const GUARDRAIL_SYSTEM_PROMPT =
  "You are a strict classifier. Given the user's last message, respond with whether it is " +
  "travel-related. Travel-related queries include destinations, attractions, lodging " +
  "(hotels/BnBs), room availability, prices, or weather in Cornwall/England.";

const llmGuardrail = llmModel.withStructuredOutput(GuardrailDecision);

async function routerAgentNode(state: typeof MessagesAnnotation.State) {
  const lastMsg = state.messages.at(-1);
  if (!(lastMsg instanceof HumanMessage)) return new Command({ goto: "travel_info_agent" });
  const userInput = lastMsg.content as string;

  // ① 护栏：先判断是不是旅行相关
  const decision = await llmGuardrail.invoke([
    new SystemMessage(GUARDRAIL_SYSTEM_PROMPT), new HumanMessage(userInput)]);

  if (!decision.is_travel) {
    return new Command({                                       // 写入拒绝语，跳到快速出口
      update: { messages: [new AIMessage(
        "Sorry, I can only help with travel-related questions (destinations, attractions, " +
        "lodging, prices, availability, or weather in Cornwall/England). " +
        "Please rephrase your request to be travel-related.")] },
      goto: "guardrail_refusal",
    });
  }

  // ② 通过护栏后，照常路由
  const { agent } = await llmRouter.invoke([
    new SystemMessage(ROUTER_SYSTEM_PROMPT), new HumanMessage(userInput)]);
  return new Command({ goto: agent });
}

const travelAssistant = new StateGraph(MessagesAnnotation)
  .addNode("router_agent", routerAgentNode,
    { ends: ["travel_info_agent", "accommodation_booking_agent", "guardrail_refusal"] })
  .addNode("travel_info_agent", travelInfoAgent)
  .addNode("accommodation_booking_agent", accommodationBookingAgent)
  .addNode("guardrail_refusal", () => ({}))                    // 空节点：通往 END 的落脚点

record GuardrailDecision(
        @Description("True if the user question is about travel information: destinations, "
                + "attractions, lodging (hotels/BnBs), prices, availability, or weather in Cornwall/England.")
        boolean isTravel,
        @Description("Brief justification for the decision.") String reason) {}

interface Guardrail {
    @SystemMessage("""
            You are a strict classifier. Given the user's last message, respond with whether
            it is travel-related. Travel-related queries include destinations, attractions,
            lodging (hotels/BnBs), room availability, prices, or weather in Cornwall/England.""")
    GuardrailDecision check(String userMessage);
}

class GuardedRouterAssistant {
    private static final String REFUSAL = """
            Sorry, I can only help with travel-related questions (destinations, attractions,
            lodging, prices, availability, or weather in Cornwall/England).
            Please rephrase your request to be travel-related.""";

    private final Guardrail guardrail;
    private final RouterAssistant router;      // 第 12 章的路由器

    String chat(String userMessage) {
        // ① 护栏：不相关就直接返回拒绝语，后面的一切都不执行
        if (!guardrail.check(userMessage).isTravel()) {
            return REFUSAL;
        }
        // ② 通过护栏后，照常路由
        return router.chat(userMessage);
    }
}

💡 拒绝语用固定文本，而不是让模型生成

被拦下的请求直接返回一段写死的拒绝语：零成本、零延迟、措辞完全可控。 更重要的是，可疑的输入根本没有机会进入主模型 —— 这也是防御提示词注入的基本思路。

第二道：智能体层护栏

路由层的规则是「旅行相关」，比较宽。「巴黎有什么好玩的？」是旅行问题，会通过第一道护栏； 但我们的知识库只有康沃尔，模型答不出来就可能开始编。所以在每个智能体内部再加一道更严的检查。

预置的 ReAct 智能体提供了一个钩子 pre_model_hook：每次调用模型之前都会先执行它。 我们用它来检查，不合规时改写发给模型的消息 —— 在最前面插一条「请礼貌拒绝」的指令。 

AGENT_GUARDRAIL_SYSTEM_PROMPT = (
    "You are a strict classifier. Given the user's last message, respond with whether it is "
    "travel-related. Travel-related queries include destinations, attractions, lodging "
    "(hotels/BnBs), room availability, prices, or weather in Cornwall/England. "
    "Only accept travel-related questions covering Cornwall (England) and reject any "
    "questions from other areas in England and from other countries")

AGENT_REFUSAL_INSTRUCTION = (
    "You can only help with travel-related questions (destinations, attractions, lodging, "
    "prices, availability, or weather in Cornwall/England). The user's request is not "
    "travel-related. Or it might be a travel related question but not focusing on Cornwall "
    "(England). Politely refuse and briefly explain what topics you can help with.")

def pre_model_guardrail(state: dict):
    messages = state.get("messages", [])
    last_msg = messages[-1] if messages else None
    if not isinstance(last_msg, HumanMessage):
        return {}                     # 最后一条是工具结果等 → 循环进行中，不用再检查

    decision = llm_guardrail.invoke([
        SystemMessage(content=AGENT_GUARDRAIL_SYSTEM_PROMPT),
        HumanMessage(content=last_msg.content)])

    if decision.is_travel:
        return {}                     # 放行：不做任何修改

    # 拦截：只改「这一次发给模型的输入」，不改状态里保存的消息
    return {"llm_input_messages": [
        SystemMessage(content=AGENT_REFUSAL_INSTRUCTION), *messages]}

async function preModelGuardrail(state: typeof MessagesAnnotation.State) {
  const lastMsg = state.messages.at(-1);
  if (!(lastMsg instanceof HumanMessage)) return {};      // 循环进行中，不用再检查

  const decision = await llmGuardrail.invoke([
    new SystemMessage(AGENT_GUARDRAIL_SYSTEM_PROMPT),
    new HumanMessage(lastMsg.content as string)]);

  if (decision.is_travel) return {};                      // 放行：不做任何修改

  // 拦截：只改「这一次发给模型的输入」，不改状态里保存的消息
  return { llmInputMessages: [new SystemMessage(AGENT_REFUSAL_INSTRUCTION), ...state.messages] };
}

// LangChain4j 的声明式输入护栏：在 AI Service 调用模型之前执行。
import dev.langchain4j.guardrail.InputGuardrail;
import dev.langchain4j.guardrail.InputGuardrailResult;
import dev.langchain4j.service.guardrail.InputGuardrails;

interface CornwallClassifier {
    @SystemMessage("""
            You are a strict classifier. Given the user's last message, respond with whether
            it is travel-related. Only accept travel-related questions covering Cornwall
            (England) and reject any questions from other areas in England and from other
            countries.""")
    GuardrailDecision check(String userMessage);
}

public class CornwallGuardrail implements InputGuardrail {
    private final CornwallClassifier classifier;
    public CornwallGuardrail(CornwallClassifier classifier) { this.classifier = classifier; }

    @Override
    public InputGuardrailResult validate(dev.langchain4j.data.message.UserMessage userMessage) {
        GuardrailDecision decision = classifier.check(userMessage.singleText());
        return decision.isTravel()
                ? success()                                            // 放行
                : fatal("I can only help with travel questions about Cornwall (England).");   // 拦截
    }
}

interface TravelInfoAgent {
    @SystemMessage("You are a helpful assistant that can search travel information ...")
    @InputGuardrails(CornwallGuardrail.class)               // ← 挂上护栏
    String chat(String userMessage);
}

// 被拦截时调用方会收到 InputGuardrailException，捕获后把其中的消息返回给用户即可。
// （Python 版是让模型「礼貌拒绝」，这里是直接短路 —— 两种处理方式各有适用场合。）

两个细节：

  • 只检查用户消息。pre_model_hook 在 ReAct 循环的每一圈都会触发；如果最后一条消息是工具结果，说明这一轮已经通过检查，直接放行，避免重复分类。
  • llm_input_messages 不改变状态。它只影响「这一次发给模型的内容」，注入的拒绝指令不会被存进对话历史，也就不会污染后续的对话。
You: Write me a Python function to sort a list.
Assistant: Sorry, I can only help with travel-related questions ...        ← 第一道（路由层）拦下

You: What can I see in Paris?
Assistant: I'm sorry, but I can only help with travel questions about Cornwall, England —
           for example destinations, attractions, accommodation or weather there.   ← 第二道（智能体层）拦下

You: What can I see in Penzance?
Assistant: In Penzance you can visit ...                                   ← 正常回答
⚠ 护栏的代价和局限
  • 每道护栏都是一次额外的 LLM 调用。分类任务简单，用最小最快的模型就行，不要用主模型。
  • 会误伤。分类器可能把正常问题判成不相关。上线后要监控被拦截的请求，持续调整分类提示词。
  • 只看单条消息有盲区。「那里呢？」脱离上下文就无法判断是否相关。更稳妥的做法是把最近几轮对话一起交给分类器。
  • 基于 LLM 的护栏不是安全边界。精心构造的输入有可能骗过分类器。真正的权限控制（谁能读哪些数据、能执行哪些操作）必须在工具和数据库层面用确定性的代码实现。

上线之前，还有这些功课

记忆和护栏是重要的里程碑，但不是终点。原书最后一节列出了生产化路上的其余关卡：

长期记忆

让助手跨会话记住用户（偏好的目的地、常订的住宿类型）。LangGraph 提供了与检查点配套的 Store 接口： 检查点按 thread_id 存「对话状态」，Store 按用户等命名空间存「长期事实」，并支持语义检索。 难点不在技术而在治理：存什么、存多久、用户如何查看和删除自己的数据。

人工介入（Human-in-the-loop）

有些决定不该由智能体独自做：行程是否安全可行、突发天气或罢工时的建议、需要向商家确认的无障碍需求…… LangGraph 的做法是让图在某个节点暂停（interrupt），把当前状态存入检查点，等人工审核后再恢复执行 —— 这正是建立在本章的检查点机制之上的。产品上线初期尤其值得这么做：人工审核的记录会成为改进护栏、提示词和知识库的依据。

输出护栏（Post-model guardrails）

本章的护栏都在模型之前。模型之后同样需要把关：

  • 过滤过时或错误的信息（已经永久关闭的景点、已经结束的活动）；
  • 脱敏（只应在预订确认后才提供的民宿联系电话）；
  • 统一品牌语气；
  • 校验结构化输出的格式（报价、行程单是否符合下游系统的要求）。

评估

最容易被忽视、也最不可或缺的一环。改了一句提示词、换了一个模型，怎么知道整体是变好还是变坏？需要一套可以反复运行的测试：

测试类型检查什么例子
功能测试回答是否正确、相关、完整「康沃尔适合家庭的海滩」「St Ives 现在的天气」
行为测试是否遵守策略、语气是否得体超出范围的问题是否被礼貌拒绝
性能测试延迟和 API 费用模拟暑期旅游旺季的请求高峰
回归测试改动后原有能力是否退化每次修改后，对照一组标准答案重跑

LangSmith 除了追踪，也提供数据集和评估功能，可以把线上的真实追踪记录沉淀成测试用例。

部署

怎么部署取决于组织的基础设施和合规要求：自建（把图包在一个 Web 服务里，配上持久化的检查点保存器）， 或使用托管服务。LangChain 官方的托管方案是 LangGraph Platform，它替你处理了持久化、任务队列、流式输出、 水平扩展这些有状态长任务特有的麻烦事。

小结

  • 记忆分三种：短期（一次会话内）、用户级长期（跨会话）、应用级长期（所有用户共享）。
  • LangGraph 用检查点实现短期记忆：编译时配 checkpointer，调用时带 thread_id，每一步的状态自动保存和恢复。
  • 检查点还带来了时间旅行：查看历史状态、从过去的时刻重放，以及人工介入所需的暂停与恢复。
  • InMemorySaver 只适合开发；生产环境用 SQLite / Postgres 等持久化保存器。
  • 护栏把助手约束在预定范围内。输入护栏本质上是一次「分类」：通过则放行，否则走快速出口。
  • 可以分层设防：路由层用宽规则直接返回固定拒绝语；智能体层用 pre_model_hook 施加更细的规则。
  • LLM 护栏会误判，也可能被绕过，不能代替工具和数据层面的确定性权限控制。
  • 通往生产还需要：长期记忆、人工介入、输出护栏、系统化评估、可靠的部署。

动手练习

  1. 对比 main_05_01.py（无记忆）和 main_08_01.py（有记忆）：分别问「Penzance 的天气」然后追问「那里有酒店吗」。
  2. 开两个终端各跑一个 main_08_01.py（两个不同的 thread_id），确认它们的对话互不影响。
  3. 聊三轮之后打印 get_state_history，数一数有多少个检查点；找出消息数第一次超过 5 的那个。
  4. 测试两道护栏：各想三个应该被第一道拦下、应该被第二道拦下、应该正常回答的问题。有没有被误判的？
  5. 改进护栏：让分类器同时看到最近 4 条消息，这样「那里呢？」这类追问不会被误拦。
  6. 思考题：如果要加一个「真的下单预订」的工具，你会在哪里加入人工确认？确认前后的状态应该怎么保存？
