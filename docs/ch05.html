第 5 章

用 LangGraph 构建智能体工作流

上一章的研究引擎是一条直线：不管搜回来的东西好不好，都会一路走到写报告。 这一章给它加上「检查一下，不行就重来」的能力。链做不到回头，所以我们换一种更强的结构：图。

本章目标

  • 分清「工作流」和「智能体」这两个常被混用的词
  • 掌握 LangGraph 的四个核心概念：状态、节点、边、条件边
  • 把第 4 章的链式研究引擎改造成图
  • 加入相关性评估和重试循环
  • 知道什么时候该用链，什么时候该用图

工作流与智能体

这两个词经常被混着用，但区别很重要：

工作流（agentic workflow）智能体（agent）
流程固定的步骤和有限的分支运行时动态生成
LLM 的角色在预设选项中做选择推理、决策、挑选和组合工具
可预测性高，容易测试和调试低，同一个问题可能走不同路径
适合流程明确的业务开放式、事先无法穷举步骤的任务
本教程本章第 11–14 章

工作流有两种最常见的模式：

  • 路由器（Router）：LLM 判断请求属于哪一类，转给对应的处理器。
  • 控制器 - 工作者（Controller-Worker）：控制器按一定顺序把任务分派给多个工作者，再汇总结果。
💡 先别急着上智能体

两者没有清晰的分界线，也没有谁更「高级」。能用工作流解决就用工作流 —— 更便宜、更快、更可控。 只有当任务确实需要显式的状态管理和动态决策时，才值得承担智能体带来的额外复杂度。 Anthropic 的文章《Building Effective Agents》把这一点讲得很透，推荐一读。

为什么链不够用了

链（LCEL）擅长「数据一路往下流」。但遇到下面三种需求就捉襟见肘：

🔀

分支

根据中间结果走不同的路。

🔄

循环

结果不满意，回到前面某一步重来。

📦

共享状态

后面的步骤想用很早之前产生的数据，不想一路手动传递。

LangGraph 用「图」来解决这三件事。它不是 LangChain 的替代品，而是它的扩展： LangChain 提供零件（模型、提示词、检索器），LangGraph 提供把零件组织成有状态、可分支、可循环的流程的图纸。

LangGraph 的四个核心概念

状态（State）
一个有明确字段和类型的数据结构，在整个图里流动。任何节点都能读到里面的所有字段 —— 不用再像链那样把 user_question 一站一站往下传。
节点（Node）
一个普通函数：输入当前状态，返回想要更新的字段。注意是只返回「变化的部分」，LangGraph 负责把它合并进状态。
边（Edge）
规定「A 做完之后轮到 B」。
条件边（Conditional Edge）
一个路由函数：读取状态，返回下一个节点的名字。分支和循环全靠它。

最小示例

from typing import TypedDict
from langgraph.graph import StateGraph, END

class ResearchState(TypedDict):            # ① 定义状态
    input_query: str
    final_output: str

def process_node(state: dict) -> dict:     # ② 定义节点：读状态，返回更新
    result = state["input_query"].upper()
    return {"final_output": result}

graph = StateGraph(ResearchState)          # ③ 组装
graph.add_node("process", process_node)
graph.set_entry_point("process")           #    入口
graph.add_edge("process", END)             #    出口

app = graph.compile()                      # ④ 编译并运行
print(app.invoke({"input_query": "hello"}))
# {'input_query': 'hello', 'final_output': 'HELLO'}

改造计划：给研究引擎加一个「质检员」

目标：在「逐页摘要」之后加一个相关性评估节点。如果相关的摘要不到一半，就回到「生成搜索查询」，换个角度重新搜； 最多重试三轮，避免无限循环。

from typing import List, Dict, Any, TypedDict, Optional

class AssistantInfo(TypedDict):

    assistant_instructions: str
    user_question: str

class SearchQuery(TypedDict):
    search_query: str
    user_question: str

class SearchResult(TypedDict):
    result_url: str
    search_query: str
    user_question: str

class SearchSummary(TypedDict):
    summary: str
    result_url: str
    user_question: str

class ResearchState(TypedDict):                       # 整个图共享的状态
    user_question: str
    assistant_info: Optional[AssistantInfo]
    search_queries: Optional[List[SearchQuery]]
    search_results: Optional[List[SearchResult]]
    search_summaries: Optional[List[SearchSummary]]
    research_summary: Optional[str]
    final_report: Optional[str]
    relevance_evaluation: Optional[Dict[str, Any]]
    should_regenerate_queries: Optional[bool]

import { Annotation } from "@langchain/langgraph";

export type AssistantInfo = {
  assistant_type: string; assistant_instructions: string; user_question: string };
export type SearchQuery = { search_query: string; user_question: string };
export type SearchResult = SearchQuery & { result_url: string };
export type SearchSummary = { summary: string; result_url: string; user_question: string };

export const ResearchState = Annotation.Root({        // 整个图共享的状态
  user_question: Annotation<string>,
  assistant_info: Annotation<AssistantInfo | null>,
  search_queries: Annotation<SearchQuery[] | null>,
  search_results: Annotation<SearchResult[] | null>,
  search_summaries: Annotation<SearchSummary[] | null>,
  research_summary: Annotation<string | null>,
  final_report: Annotation<string | null>,
  relevance_evaluation: Annotation<Record<string, any> | null>,
  should_regenerate_queries: Annotation<boolean | null>,
  iteration_count: Annotation<number>,
});
export type State = typeof ResearchState.State;

import org.bsc.langgraph4j.state.AgentState;

// LangGraph4j 的状态底层是一个 Map，我们给它包一层带类型的访问方法。
public class ResearchState extends AgentState {
    public ResearchState(Map<String, Object> data) { super(data); }

    public String userQuestion()      { return this.<String>value("user_question").orElseThrow(); }
    public AssistantInfo assistant()  { return this.<AssistantInfo>value("assistant_info").orElse(null); }
    public List<SearchQuery> queries(){ return this.<List<SearchQuery>>value("search_queries").orElse(List.of()); }
    public List<SearchResult> results(){ return this.<List<SearchResult>>value("search_results").orElse(List.of()); }
    public List<String> summaries()   { return this.<List<String>>value("search_summaries").orElse(List.of()); }
    public String researchSummary()   { return this.<String>value("research_summary").orElse(""); }
    public boolean shouldRegenerate() { return this.<Boolean>value("should_regenerate_queries").orElse(false); }
    public int iterationCount()       { return this.<Integer>value("iteration_count").orElse(0); }
}

第二步：把每条链改写成节点函数

套路完全一样：从状态里取需要的字段 → 干活 → 返回要更新的字段。先看最简单的两个： 

import json

def select_assistant(state: dict) -> dict:
    """根据用户问题选择合适的研究助手。"""
    user_question = state["user_question"]
    prompt = ASSISTANT_SELECTION_PROMPT_TEMPLATE.format(user_question=user_question)
    response_text = get_llm().invoke(prompt).content

    try:
        # 模型有时会在 JSON 前后加说明文字，所以只截取第一个 { 到最后一个 } 之间的部分
        json_str = response_text[response_text.find('{'): response_text.rfind('}') + 1]
        return {"assistant_info": json.loads(json_str)}
    except Exception:
        # 解析失败就用一个通用助手兜底，而不是让整个流程崩掉
        return {"assistant_info": {
            "assistant_type": "General research assistant",
            "assistant_instructions": "You are a general research AI assistant. ...",
            "user_question": user_question}}

def write_research_report(state: dict) -> dict:
    """根据汇总后的摘要撰写研究报告。"""
    prompt = RESEARCH_REPORT_PROMPT_TEMPLATE.format(
        research_summary=state["research_summary"],
        user_question=state["user_question"])

export async function selectAssistant(state: State) {
  const prompt = await ASSISTANT_SELECTION_PROMPT_TEMPLATE.format({
    user_question: state.user_question });
  const text = (await getLlm().invoke(prompt)).content as string;

  try {
    // 只截取第一个 { 到最后一个 } 之间的部分
    const jsonStr = text.slice(text.indexOf("{"), text.lastIndexOf("}") + 1);
    return { assistant_info: JSON.parse(jsonStr) as AssistantInfo };
  } catch {
    // 解析失败就用一个通用助手兜底
    return { assistant_info: {
      assistant_type: "General research assistant",
      assistant_instructions: "You are a general research AI assistant. ...",
      user_question: state.user_question } };
  }
}

export async function writeResearchReport(state: State) {
  const prompt = await RESEARCH_REPORT_PROMPT_TEMPLATE.format({
    research_summary: state.research_summary, user_question: state.user_question });
  return { final_report: (await getLlm().invoke(prompt)).content as string };

static Map<String, Object> selectAssistant(Researcher ai, ResearchState state) {
    try {
        return Map.of("assistant_info", ai.selectAssistant(state.userQuestion()));
    } catch (Exception e) {
        // 解析失败就用一个通用助手兜底
        return Map.of("assistant_info", new AssistantInfo(
                "General research assistant",
                "You are a general research AI assistant. ...",
                state.userQuestion()));
    }
}

static Map<String, Object> writeResearchReport(Researcher ai, ResearchState state) {
    return Map.of("final_report",
            ai.writeReport(state.researchSummary(), state.userQuestion()));
}

第三步：会「换个搜法」的查询生成节点

这个节点可能被执行多次。第一次正常生成查询；重试时，它会把上一轮的查询和评估意见告诉模型，要求换个思路。 

NUM_SEARCH_QUERIES = 3

def generate_search_queries(state: dict) -> dict:
    assistant_instructions = state["assistant_info"]["assistant_instructions"]
    user_question = state["user_question"]
    iteration_count = state.get("iteration_count", 0)
    previous_queries = state.get("search_queries") or []
    evaluation = state.get("relevance_evaluation") or {}

    if iteration_count == 0:
        # 第一次：用标准提示词
        prompt = WEB_SEARCH_PROMPT_TEMPLATE.format(
            assistant_instructions=assistant_instructions,
            user_question=user_question,
            num_search_queries=NUM_SEARCH_QUERIES)
    else:
        # 重试：告诉模型上次哪里不行，要求完全不同的查询
        previous = ", ".join(q["search_query"] for q in previous_queries)
        prompt = f"""
        {assistant_instructions}
        You are generating new search queries because the previous queries did not yield
        sufficiently relevant results.
        Original question: {user_question}
        Previous search queries: {previous}
        Relevance evaluation: {evaluation.get("relevance_percentage", 0)}% relevant
        Explanation: {evaluation.get("explanation", "")}
        Please generate {NUM_SEARCH_QUERIES} NEW and DIFFERENT web search queries that are
        MORE SPECIFIC and TARGETED. DO NOT repeat or rephrase the previous queries.
        You must respond with a list of queries in the following format:
        [ {{"search_query": "query1", "user_question": "{user_question}" }}, ... ]
        """

    text = get_llm().invoke(prompt).content
    queries = json.loads(text[text.find('['): text.rfind(']') + 1])

    return {"search_queries": queries,
            "relevance_evaluation": None,          # 新一轮开始，清掉旧的评估结果
            "should_regenerate_queries": None}

const NUM_SEARCH_QUERIES = 3;

export async function generateSearchQueries(state: State) {
  const instructions = state.assistant_info!.assistant_instructions;
  const question = state.user_question;
  const evaluation = state.relevance_evaluation ?? {};
  let prompt: string;

  if ((state.iteration_count ?? 0) === 0) {
    // 第一次：用标准提示词
    prompt = await WEB_SEARCH_PROMPT_TEMPLATE.format({
      assistant_instructions: instructions, user_question: question,
      num_search_queries: NUM_SEARCH_QUERIES });
  } else {
    // 重试：告诉模型上次哪里不行，要求完全不同的查询
    const previous = (state.search_queries ?? []).map((q) => q.search_query).join(", ");
    prompt = `
      ${instructions}
      You are generating new search queries because the previous queries did not yield
      sufficiently relevant results.
      Original question: ${question}
      Previous search queries: ${previous}
      Relevance evaluation: ${evaluation.relevance_percentage ?? 0}% relevant
      Explanation: ${evaluation.explanation ?? ""}
      Please generate ${NUM_SEARCH_QUERIES} NEW and DIFFERENT web search queries that are
      MORE SPECIFIC and TARGETED. DO NOT repeat or rephrase the previous queries.
      You must respond with a list of queries in the following format:
      [ {"search_query": "query1", "user_question": "${question}" }, ... ]`;
  }

  const text = (await getLlm().invoke(prompt)).content as string;
  const queries: SearchQuery[] =
    JSON.parse(text.slice(text.indexOf("["), text.lastIndexOf("]") + 1));

  return { search_queries: queries,
           relevance_evaluation: null,           // 新一轮开始，清掉旧的评估结果
           should_regenerate_queries: null };
}

// 在 Researcher 接口里再加一个「重试用」的方法：
//   @UserMessage(fromResource = "prompts/web_search_retry.txt")
//   List<SearchQuery> rewriteQueries(@V("assistant_instructions") String instructions,
//                                    @V("user_question") String question,
//                                    @V("previous_queries") String previous,
//                                    @V("explanation") String explanation);

static Map<String, Object> generateSearchQueries(Researcher ai, ResearchState state) {
    String instructions = state.assistant().assistantInstructions();
    List<SearchQuery> queries;

    if (state.iterationCount() == 0) {
        queries = ai.writeQueries(instructions, 3, state.userQuestion());       // 第一次
    } else {
        String previous = state.queries().stream()                              // 重试
                .map(SearchQuery::searchQuery).collect(Collectors.joining(", "));
        String explanation = state.<String>value("relevance_explanation").orElse("");
        queries = ai.rewriteQueries(instructions, state.userQuestion(), previous, explanation);
    }
    return Map.of("search_queries", queries, "should_regenerate_queries", false);
}

第四步：质检节点 —— 用 LLM 评估 LLM 的产出

def evaluate_search_relevance(state: dict) -> dict:
    """评估摘要与原问题的相关性；不足 50% 则要求重新生成查询。"""
    search_summaries = state.get("search_summaries") or []
    iteration_count = state.get("iteration_count", 0) + 1     # 记一轮

    if not search_summaries:
        return {"should_regenerate_queries": True, "iteration_count": iteration_count}

    prompt = f"""
    Evaluate whether each of the following summaries is relevant to the question.
    Question: {state["user_question"]}
    Summaries:
    {state["research_summary"]}

    Respond in JSON:
    {{"relevance_percentage": <0-100>, "explanation": "<one or two sentences>"}}
    """
    text = get_llm().invoke(prompt).content
    evaluation = json.loads(text[text.find('{'): text.rfind('}') + 1])

    return {"relevance_evaluation": evaluation,
            "should_regenerate_queries": evaluation["relevance_percentage"] < 50,
            "iteration_count": iteration_count}

export async function evaluateSearchRelevance(state: State) {
  const iteration_count = (state.iteration_count ?? 0) + 1;    // 记一轮

  if (!state.search_summaries?.length) {
    return { should_regenerate_queries: true, iteration_count };
  }

  const prompt = `
    Evaluate whether each of the following summaries is relevant to the question.
    Question: ${state.user_question}
    Summaries:
    ${state.research_summary}

    Respond in JSON:
    {"relevance_percentage": <0-100>, "explanation": "<one or two sentences>"}`;

  const text = (await getLlm().invoke(prompt)).content as string;
  const evaluation = JSON.parse(text.slice(text.indexOf("{"), text.lastIndexOf("}") + 1));

  return { relevance_evaluation: evaluation,
           should_regenerate_queries: evaluation.relevance_percentage < 50,
           iteration_count };
}

record RelevanceEvaluation(int relevancePercentage, String explanation) {}

// Researcher 接口里再加：
//   @UserMessage("""
//       Evaluate whether each of the following summaries is relevant to the question.
//       Question: {{question}}
//       Summaries:
//       {{summaries}}""")
//   RelevanceEvaluation evaluate(@V("question") String q, @V("summaries") String s);

static Map<String, Object> evaluateSearchRelevance(Researcher ai, ResearchState state) {
    int iterationCount = state.iterationCount() + 1;                 // 记一轮

    if (state.summaries().isEmpty()) {
        return Map.of("should_regenerate_queries", true, "iteration_count", iterationCount);
    }
    RelevanceEvaluation eval = ai.evaluate(state.userQuestion(), state.researchSummary());

    return Map.of("relevance_explanation", eval.explanation(),
                  "should_regenerate_queries", eval.relevancePercentage() < 50,
                  "iteration_count", iterationCount);
}

from langgraph.graph import StateGraph, END

MAX_ITERATIONS = 3

def route_based_on_relevance(state: dict) -> str:
    """条件边：只读状态，返回下一个节点的名字。"""
    if state.get("iteration_count", 0) >= MAX_ITERATIONS:
        return "write_research_report"            # 到上限了，有什么写什么
    if state.get("should_regenerate_queries", False):
        return "generate_search_queries"          # 不够相关，回去重搜
    return "write_research_report"

def create_research_graph() -> StateGraph:
    graph = StateGraph(ResearchState)

    graph.add_node("select_assistant", select_assistant)
    graph.add_node("generate_search_queries", generate_search_queries)
    graph.add_node("perform_web_searches", perform_web_searches)
    graph.add_node("summarize_search_results", summarize_search_results)
    graph.add_node("evaluate_search_relevance", evaluate_search_relevance)
    graph.add_node("write_research_report", write_research_report)

    graph.set_entry_point("select_assistant")
    graph.add_edge("select_assistant", "generate_search_queries")
    graph.add_edge("generate_search_queries", "perform_web_searches")
    graph.add_edge("perform_web_searches", "summarize_search_results")
    graph.add_edge("summarize_search_results", "evaluate_search_relevance")

    graph.add_conditional_edges(
        "evaluate_search_relevance",
        route_based_on_relevance,
        {"generate_search_queries": "generate_search_queries",
         "write_research_report": "write_research_report"})

    graph.add_edge("write_research_report", END)
    return graph

  if (state.should_regenerate_queries) return "generate_search_queries";
  return "write_research_report";
}

        .addNode("perform_web_searches",      node_async(Nodes::performWebSearches))
        .addNode("summarize_search_results",  node_async(s -> Nodes.summarizeSearchResults(ai, s)))
        .addNode("evaluate_search_relevance", node_async(s -> Nodes.evaluateSearchRelevance(ai, s)))
        .addNode("write_research_report",     node_async(s -> Nodes.writeResearchReport(ai, s)))

        .addEdge(START, "select_assistant")
        .addEdge("select_assistant", "generate_search_queries")
        .addEdge("generate_search_queries", "perform_web_searches")
        .addEdge("perform_web_searches", "summarize_search_results")
        .addEdge("summarize_search_results", "evaluate_search_relevance")

        // 条件边：路由函数返回一个「标签」，后面的 Map 把标签映射到节点名
        .addConditionalEdges("evaluate_search_relevance",
                edge_async(s -> {
                    if (s.iterationCount() >= MAX_ITERATIONS) return "report";
                    return s.shouldRegenerate() ? "retry" : "report";
                }),
                Map.of("retry", "generate_search_queries",
                       "report", "write_research_report"))

        .addEdge("write_research_report", END)
        .compile();

var result = app.invoke(Map.of(
        "user_question", "What can you tell me about Astorga's roman spas",
        "iteration_count", 0));
System.out.println(result.orElseThrow().<String>value("final_report").orElse(""));
⚠ 路由函数里不要改状态

条件边的路由函数应该是只读的：读状态，返回去向，仅此而已。在路由函数里直接修改 state，改动不会被保存。 想更新状态（比如给 iteration_count 加一），必须在节点的返回值里做 —— 所以上面把计数放进了评估节点。 仓库里 ch05/main.py 的原始写法是在路由函数里自增计数，读代码时留意这一点。

⚠ 有循环，就必须有出口

MAX_ITERATIONS 不是可有可无的。如果问题本身就搜不到好结果，没有上限的循环会一直烧钱。 任何带回边的图都要问自己一句：最坏情况下它会转几圈？

链 vs 图：到底换来了什么

第 4 章：LCEL 链本章：LangGraph 图
数据怎么传上一步的输出就是下一步的输入，需要的字段得一路带着所有节点读写同一份状态
分支与循环很别扭，或者做不到条件边，原生支持
并行.map() 一行搞定要自己在节点里并发，或用 Send API
调试中间数据藏在管道里每一步之后的完整状态都能打印出来
代码量少多一些（要定义状态、节点、边）
适合线性流水线需要决策、重试、长时间运行的流程
🔑 两者是搭档，不是对手

图的节点内部完全可以是一条 LCEL 链。常见的做法是： 用链处理「一个节点里的事」（模板 → 模型 → 解析），用图处理「节点之间的事」（先谁后谁、要不要回头）。

小结

  • 工作流走预设路线，LLM 只做选择；智能体由 LLM 动态决定下一步。能用工作流就先用工作流。
  • 链处理不了分支、循环和跨步骤共享的状态；LangGraph 用图来解决。
  • 四个核心概念：状态（共享记事本）、节点（读状态、返回更新的函数）、边、条件边（读状态、返回去向的函数）。
  • 节点只返回要更新的字段；路由函数只读不写。
  • 「让 LLM 评估结果，不合格就重试」是一个通用且好用的模式，但循环必须设上限。
  • 链和图配合使用：节点内部用链，节点之间用图。
