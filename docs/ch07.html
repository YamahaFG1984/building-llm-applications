第 7 章

问答机器人与 LangSmith

上一章手写了一个最小的 RAG。现在用框架把它做成真正的问答机器人： 能吃进各种格式的文档、能记住上文接着聊，还能把每一次运行的内部细节摊开来看 —— 后者靠的是 LangSmith。

本章目标

  • 认识 RAG 两个阶段各自用到的 LangChain 对象
  • 把维基百科、Word、PDF、文本文件批量入库
  • 用检索器 + 提示词 + 模型搭一条 RAG 链
  • 给机器人加上对话记忆，让它听得懂「然后呢？」
  • 用 LangSmith 追踪和调试链的执行

对象模型：谁负责什么

先看全景。上一章手写的每一步，在 LangChain 里都有一个对应的对象：

ⓘ RecursiveCharacterTextSplitter 的「递归」是什么意思

它不会机械地每 500 个字符切一刀，而是先尝试按段落（空行）切；某一段还是太长，再按换行切； 再不行按句子、按单词…… 这样切出来的块尽量保持语义完整，是最常用的默认切分器。

四种来源，同一套动作

每种文档都是「加载 → 切分 → 入库」。写四遍就能发现重复，所以直接提炼成一个函数：

def split_and_import(loader):
    chunks = text_splitter.split_documents(loader.load())
    vector_db.add_documents(chunks)
    print(f"Ingested chunks created by {loader}")

async function splitAndImport(loader: BaseDocumentLoader) {

整个文件夹一起入库

文件一多，逐个写就不现实了。做一个加载器工厂：看扩展名决定用哪个加载器，再遍历文件夹。 仓库里用来练习的是 CilentoTouristInfo/ 目录。 

import os

loader_classes = {
    'docx': Docx2txtLoader,
    'pdf': PyPDFLoader,
    'txt': TextLoader
}

def get_loader(filename):
    _, file_extension = os.path.splitext(filename)
    file_extension = file_extension.lstrip('.')
    loader_class = loader_classes.get(file_extension)
    if loader_class:
        return loader_class(filename)
    raise ValueError(f"No loader available for file extension '{file_extension}'")

folder_path = "CilentoTouristInfo"
for filename in os.listdir(folder_path):
    file_path = os.path.join(folder_path, filename)
    if os.path.isfile(file_path):
        try:
            split_and_import(get_loader(file_path))
        except ValueError as e:
            print(e)              # 不认识的格式：跳过并提示，不中断整个流程

import { readdir } from "node:fs/promises";
import path from "node:path";

const loaderClasses: Record<string, new (p: string) => BaseDocumentLoader> = {
  ".docx": DocxLoader,
  ".pdf": PDFLoader,
  ".txt": TextLoader,
};

function getLoader(filename: string): BaseDocumentLoader {
  const LoaderClass = loaderClasses[path.extname(filename).toLowerCase()];
  if (!LoaderClass) {
    throw new Error(`No loader available for file extension '${path.extname(filename)}'`);
  }
  return new LoaderClass(filename);
}

const folderPath = "CilentoTouristInfo";
for (const entry of await readdir(folderPath, { withFileTypes: true })) {
  if (!entry.isFile()) continue;
  try {
    await splitAndImport(getLoader(path.join(folderPath, entry.name)));
  } catch (e) {
    console.warn(String(e));      // 不认识的格式：跳过并提示
  }
}

💡 先看检索，再看生成

RAG 回答得不好，十有八九是检索出了问题 —— 相关的文本块根本没被找出来，模型再强也无米下炊。 所以调试时永远先单独检查检索结果。

搭一条 RAG 链

把向量库包装成检索器（Retriever），它就成了一块可以接进链里的标准积木：输入问题字符串，输出文档列表。

from langchain_core.prompts import PromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI

rag_prompt = PromptTemplate.from_template(
"""Use the following pieces of context to answer the question at the end.
If you don't know the answer, just say that you don't know,
don't try to make up an answer.
Use three sentences maximum and keep the answer as concise as possible.
{context}
Question: {question}
Helpful Answer:""")

retriever = vector_db.as_retriever()
question_feeder = RunnablePassthrough()
chatbot = ChatOpenAI(openai_api_key=OPENAI_API_KEY, model_name="gpt-5-nano")

rag_chain = {"context": retriever,
             "question": question_feeder} | rag_prompt | chatbot

def execute_chain(chain, question):
    return chain.invoke(question)

question = """Where was Poseidonia and who renamed
it to Paestum. Also tell me the source."""
print(execute_chain(rag_chain, question).content)

import { PromptTemplate } from "@langchain/core/prompts";
import { RunnablePassthrough, RunnableSequence } from "@langchain/core/runnables";
import { ChatOpenAI } from "@langchain/openai";
import type { Document } from "@langchain/core/documents";

const ragPrompt = PromptTemplate.fromTemplate(
`Use the following pieces of context to answer the question at the end.
If you don't know the answer, just say that you don't know,
don't try to make up an answer.
Use three sentences maximum and keep the answer as concise as possible.
{context}
Question: {question}
Helpful Answer:`);

const retriever = vectorDb.asRetriever();
const chatbot = new ChatOpenAI({ model: "gpt-5-nano" });

// 把文档列表拼成一段文本，并带上来源
const formatDocs = (docs: Document[]) =>
  docs.map((d) => `${d.pageContent}\n(source: ${d.metadata.source})`).join("\n\n");

const ragChain = RunnableSequence.from([
  { context: retriever.pipe(formatDocs), question: new RunnablePassthrough() },
  ragPrompt,
  chatbot,
]);

const question = `Where was Poseidonia and who renamed
it to Paestum. Also tell me the source.`;
console.log((await ragChain.invoke(question)).content);

import dev.langchain4j.rag.content.retriever.EmbeddingStoreContentRetriever;
import dev.langchain4j.service.AiServices;
import dev.langchain4j.service.SystemMessage;

var retriever = EmbeddingStoreContentRetriever.builder()
        .embeddingStore(vectorDb)
        .embeddingModel(embeddingsModel)
        .maxResults(4)
        .build();

interface TourGuide {
    @SystemMessage("""
            Use the retrieved context to answer the question.
            If you don't know the answer, just say that you don't know,
            don't try to make up an answer.
            Use three sentences maximum and keep the answer as concise as possible.""")
    String answer(String question);
}

// 给 AI Service 配一个 contentRetriever，它就自动变成 RAG：
// 每次调用前先检索，再把检索到的内容拼进用户消息里。
TourGuide chatbot = AiServices.builder(TourGuide.class)
        .chatModel(OpenAiChatModel.builder()
                .apiKey(System.getenv("OPENAI_API_KEY")).modelName("gpt-5-nano").build())
        .contentRetriever(retriever)
        .build();

System.out.println(chatbot.answer(
        "Where was Poseidonia and who renamed it to Paestum. Also tell me the source."));

链开头那个字典是关键。它让同一个问题兵分两路：

  • "context": retriever —— 问题进入检索器，出来的是相关文档；
  • "question": RunnablePassthrough() —— 问题原样通过。

两路结果合成一个 {context, question} 字典，正好填进提示词模板的两个占位符。

追问一句，它就傻了

question = """And then, what they do?
Tell me only if you know. Also tell me the source"""
print(execute_chain(rag_chain, question).content)
# I don't know.

「then」指什么时候？「they」是谁？这条链每次调用都是全新的开始，它不知道上一个问题问了什么。 要让它听懂追问，得给它加上记忆。

对话记忆

第 1 章说过：所谓记忆，就是把之前的对话再发一遍。做法分三步：

聊天提示词模板与消息角色

之前用的 PromptTemplate 生成的是一整段字符串。要表达「这句是系统说的、这句是用户说的」，需要 ChatPromptTemplate，它生成的是一组带角色的消息：

角色含义添加历史时用的方法
system开发者给模型的总体指示—
human / user用户说的话add_user_message()
ai / assistant模型说的话add_ai_message()
placeholder占位：运行时在这里插入一整串消息—

完整实现

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough, RunnableLambda
from langchain_community.chat_message_histories import ChatMessageHistory

rag_prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful assistant, world-class expert in Roman and Greek "
               "history, especially in towns located in southern Italy. Provide "
               "interesting insights on local history and recommend places to visit "
               "with knowledgeable and engaging answers. Answer all questions to the "
               "best of your ability, but only use what has been provided in the context. "
               "If you don't know, just say you don't know."),
    ("placeholder", "{chat_history_messages}"),
    ("assistant", "{retrieved_context}"),
    ("human", "{question}"),
])

retriever = vector_db.as_retriever()
chatbot = ChatOpenAI(openai_api_key=OPENAI_API_KEY, model_name="gpt-5-nano")

chat_history_memory = ChatMessageHistory()

def get_messages(x):
    return chat_history_memory.messages

rag_chain = {
    "retrieved_context": retriever,
    "question": RunnablePassthrough(),
    "chat_history_messages": RunnableLambda(get_messages)     # 第三路：读取历史
} | rag_prompt | chatbot

def execute_chain_with_memory(chain, question):
    chat_history_memory.add_user_message(question)   # 先记下问题
    answer = chain.invoke(question)
    chat_history_memory.add_ai_message(answer)       # 再记下回答
    return answer

print(execute_chain_with_memory(rag_chain,
    "Where was Poseidonia and who renamed it to Paestum? Also tell me the source.").content)

print(execute_chain_with_memory(rag_chain,
    "And then what did they do? Also tell me the source").content)     # 这次能答上来了

import { ChatPromptTemplate, MessagesPlaceholder } from "@langchain/core/prompts";
import { InMemoryChatMessageHistory } from "@langchain/core/chat_history";
import { RunnableLambda } from "@langchain/core/runnables";

const ragPrompt = ChatPromptTemplate.fromMessages([
  ["system", "You are a helpful assistant, world-class expert in Roman and Greek " +
             "history, especially in towns located in southern Italy. Provide " +
             "interesting insights on local history and recommend places to visit " +
             "with knowledgeable and engaging answers. Answer all questions to the " +
             "best of your ability, but only use what has been provided in the context. " +
             "If you don't know, just say you don't know."],
  new MessagesPlaceholder("chat_history_messages"),
  ["assistant", "{retrieved_context}"],
  ["human", "{question}"],
]);

const chatHistoryMemory = new InMemoryChatMessageHistory();

const ragChain = RunnableSequence.from([
  {
    retrieved_context: retriever.pipe(formatDocs),
    question: new RunnablePassthrough(),
    chat_history_messages: RunnableLambda.from(() => chatHistoryMemory.getMessages()),
  },
  ragPrompt,
  chatbot,
]);

async function executeChainWithMemory(question: string) {
  await chatHistoryMemory.addUserMessage(question);   // 先记下问题
  const answer = await ragChain.invoke(question);
  await chatHistoryMemory.addMessage(answer);         // 再记下回答
  return answer;
}

console.log((await executeChainWithMemory(
  "Where was Poseidonia and who renamed it to Paestum? Also tell me the source.")).content);

console.log((await executeChainWithMemory(
  "And then what did they do? Also tell me the source")).content);     // 这次能答上来了

⚠ 这种记忆有三个局限
  • 会越来越长：每轮都把全部历史发出去，token 费用线性增长，迟早撑爆上下文窗口。生产环境要截断（只留最近 N 轮）或把旧对话压缩成摘要。Java 版的 MessageWindowChatMemory 做的就是截断。
  • 检索没用上历史：这里拿去检索的仍然是原始问题「然后他们做了什么？」，它本身几乎没有可检索的信息。改进办法是先让 LLM 结合历史把它改写成完整的问题 —— 第 9 章的内容。
  • 只活在内存里：程序一重启就没了，而且所有用户共用一份。第 14 章用 LangGraph 的检查点解决。

用 LangSmith 看清链的内部

链一长，出了问题就像黑盒：到底检索到了什么？最终发给模型的提示词长什么样？哪一步最慢、最费钱？ LangSmith 是 LangChain 官方的追踪平台，能把每次运行的每一步都记录下来。

开启追踪：只需要环境变量

在 smith.langchain.com 注册并创建 API Key，然后在启动程序之前设置：

#   export LANGSMITH_PROJECT="Q & A chatbot"
#   export LANGSMITH_API_KEY=<你的 LangSmith API Key>
#
# Windows 的 cmd 里把 export 换成 set

// LangChain.js 读取的是同一组环境变量，同样不用改代码：
//
//   export LANGSMITH_TRACING=true
//   export LANGSMITH_ENDPOINT=https://api.smith.langchain.com
//   export LANGSMITH_PROJECT="Q & A chatbot"
//   export LANGSMITH_API_KEY=<你的 LangSmith API Key>
//
// 也可以写进 .env，再在入口文件顶部 import "dotenv/config";

// LangSmith 没有针对 LangChain4j 的一键集成。Java 里的等价做法是注册「监听器」，
// 把每次模型调用的请求、响应、耗时、token 用量记录下来（或上报给 OpenTelemetry / Langfuse）。
import dev.langchain4j.model.chat.listener.*;

class TracingListener implements ChatModelListener {
    @Override public void onRequest(ChatModelRequestContext ctx) {
        System.out.println(">>> " + ctx.chatRequest().messages());
    }
    @Override public void onResponse(ChatModelResponseContext ctx) {
        System.out.println("<<< " + ctx.chatResponse().aiMessage().text());
        System.out.println("    tokens: " + ctx.chatResponse().tokenUsage());
    }
    @Override public void onError(ChatModelErrorContext ctx) {
        ctx.error().printStackTrace();
    }
}

var llm = OpenAiChatModel.builder()
        .apiKey(System.getenv("OPENAI_API_KEY")).modelName("gpt-5-nano")
        .listeners(List.of(new TracingListener()))
        .build();

一条追踪记录里能看到什么

排查 RAG 问题时，最常用的两个检查点：

  1. 点开 Retriever：检索回来的文本块里有没有答案？没有 → 是入库或检索的问题（第 8、9 章）。
  2. 点开 ChatOpenAI：资料明明在提示词里，模型却没用上？→ 是提示词的问题。
💡 开发阶段就一直开着

追踪不是出了事故才用的东西。LangSmith 有免费额度，开发时始终开着它，能省下大量加 print 语句的时间。 到了智能体章节（第 11 章起），执行路径是动态的，没有追踪几乎无法调试。

小结

  • 入库阶段的对象：Loader → Splitter → Embeddings → VectorStore；问答阶段：Retriever → PromptTemplate → ChatModel。
  • 不同格式的文档用不同加载器，但加载后的处理完全一样，所以可以提炼成通用函数和加载器工厂。
  • vector_db.as_retriever() 把向量库变成可以接进链里的检索器。
  • RAG 链的开头用一个字典把问题分成两路：一路去检索，一路原样通过。
  • 对话记忆 = 把历史消息放进提示词。用 ChatPromptTemplate 的占位符插入，用消息历史对象保存。
  • LangSmith 通过环境变量开启，能看到链中每一步的输入、输出、耗时和 token 用量。
  • 调试 RAG：先看检索，再看生成。

动手练习

  1. 把 CilentoTouristInfo 文件夹入库，然后问一个只有这些文件才能回答的问题（比如关于帕利努罗角）。
